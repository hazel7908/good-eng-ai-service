## 1. 결함 — 텍스트 검증으로는 절대 안 잡히는 것 ★

### 1-1. 표 캡션과 표가 쪽 분리된다 (Critical) — ✅ **2026-08-03 수정됨**

> **조치**: 베이스 문서의 캡션 문단 **27개 전부에 `KeepWithNext`("다음 문단과 함께")** 를 걸었다.
> `build_template.py` 의 `keep_captions_with_table()` 이 처리한다 — 재현 가능하다.
>
> - `hp:caption` 이 0개라 **캡션은 표에 붙은 개체가 아니라 별도 문단**이었다. 그래서 분리됐다.
> - 캡션 문단 위치는 **저장된 HWPX 를 읽어** 계산한다(표를 품은 문단의 바로 앞).
>   XML 은 읽기만 하고 **고치는 것은 한글 API** 다 (`rules/hwpx.md` 의 금지 조항 준수).
> - `GetDefault` 로 현재 문단 모양을 읽은 뒤 `KeepWithNext` 만 켠다 — 이 단계를 빼면
>   정렬·들여쓰기가 기본값으로 덮인다.
> - 괴산·청양 재생성 후 PDF 로 재확인: **캡션이 표와 함께 다음 쪽으로 넘어간다.** ✅

원래 증상은 아래와 같았다.

**괴산·청양 표 29 에서 동일하게 발생.** 앞 장 맨 아래에 캡션만 남고 표는 다음 장 맨 위에서
캡션 없이 시작한다. 캡션 아래로 페이지 절반이 빈다.

```
p18 하단 : <표 7.2.7-24> 최종 저감대책 수립 후, 예측소음도   (단위 : dB(A))
           ← 여기서 페이지 끝. 아래 절반이 공백
p19 상단 : ┌─────┬──────┬──── (표가 캡션 없이 시작)
```

- **행 수와 무관하다** — 8행(괴산)·10행(청양) 모두 발생한다.
- 원인은 표가 커져 현재 쪽에 안 들어갈 때 **표만** 다음 쪽으로 밀리는 것이다.
  캡션 문단에 "다음 문단과 함께" 속성이 없다.
- **실무에서 반려 사유급이다.** 캡션 없는 표는 표가 아니다.

### 1-2. `P - 10` 이 두 줄로 접힌다 (Major) — 원인은 열 폭이 아니었다 ★

청양 표 29 첫 열. 두 자리 PP 번호에서만 발생한다 (`P -` / `10`).

**열을 넓히는 것이 답이 아니다.** 청양 정답은 이 표에서 **`P-10`(공백 없음)** 을 쓴다.
`_variants.md` 가 "청양은 표에 따라 `P-1` 도 쓴다"고 기록한 것이 바로 이 자리다 —
**실무자가 폭에 맞춰 표기를 바꾼 것**이다.

즉 이 결함은 레이아웃 문제가 아니라 **PP 라벨 표기 문제**이며,
현재 검증에서 `P - 1` ↔ `P-1` 로 10행 전부 어긋나는 것과 **같은 원인**이다.

```
→ PP 라벨 형식을 vars 로 뺄 것 ("P - {n}" / "P-{n}")
   레이아웃과 텍스트 정확도를 한 번에 고친다
```

### 1-3. 캡션의 `(단위 : dB(A))` 가 두 줄로 접힌다 (Minor)

청양 p18. 캡션 본문이 길어지면 오른쪽 탭 위치를 넘어간다.

### 1-4. 페이지 번호가 원주 값 그대로다 (확인 필요)

천안 출력은 263–279 쪽으로 매겨진다. 정답 천안은 251–264 쪽이다.
파트를 완본에 합칠 때 다시 매기는 것이 정상이라면 문제가 아니다 — **실무 확인 항목**.
