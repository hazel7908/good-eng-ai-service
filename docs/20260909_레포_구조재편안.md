## 1. 구조적 제약 — git이 Mac↔Windows 파일 전달 통로다

생성물 hwpx(Windows 생성 → Mac 채점)·삽도 PNG(Mac 생성 → Windows 삽입)는
**git을 매체로 두 기기를 오간다.** 이 바이너리들을 레포에서 빼려면 양쪽이 접근하는
**공유 저장소(클라이언트 NAS storage)가 선행 조건**이다. → NAS storage 요청의 1순위 근거.

## 2. 분류안

### A. 지금 뺄 수 있는 것 (어느 세션도 안 씀 — 즉시 실행 가능)

- **`_archive/poc-2026-03/` 19.3MB** → `git rm` + 로컬 보관(+NAS 백업). 참조 금지
  폴더인데 커밋돼 있고, 개인정보 사본(마스킹은 09-09 완료)과 9.6MB 옛 산출물이 든다.
  참조는 `generate-report` 스킬의 "참조 금지" 문구뿐 — 같은 커밋에서 문구 갱신.
- **`catalog/data/nas_index.json.gz` 26MB** → gitignore + 로컬. NAS 전수 인덱스 —
  쓰는 곳은 Mac 카탈로그 도구뿐(crawl·diff·harvest·survey), 재생성 가능(NAS 재크롤),
  직원명 폴더 경로 포함. `stats_values/` 선례(값 본체 로컬·매니페스트 커밋) 그대로.

→ 이 둘만으로 작업 트리 **-45MB (198.7 → ~153MB)**.

### B. gitignore 정비 (파일 이동 없음 — 즉시)

- `*.psd` 명시 (현재 관행상 안 커밋되지만 규칙이 없다 — figures/ 옆에 떨어짐)
- `cases/**/figures/*.png` — ⚠️ 단 §1 제약: Windows 삽입이 커밋본을 쓰는 동안은 보류,
  NAS storage 확보 시 D와 함께
- `tmp/`·`scratch/` — 새 세션 실사용 테스트(지시 ④)에서 산출물이 레포 밖/무시 경로에
  떨어지는지 확인할 자리

### C. 레포 유지 (서비스 자산)

`engine/`(생성·검증 코드) · `templates/`(베이스 — 서비스 본체) · `.claude/`(rule·스킬) ·
`golden/*.txt`(검증·distill 자산 — 채점기·rule 스코핑이 참조, PII 정리 완료) ·
`cases/`의 텍스트층(input txt·vars json·validation·fill-report — 재현 불가한 판단 기록) ·
`docs/`·`catalog/` 코드+review.

### D. NAS storage 확보 후 이관 (전달 통로 대체 — 클라이언트 요청 사안)

- cases 생성물 hwpx/pdf 33.8MB (레포에는 추출 txt만 남기는 방향)
- cases 삽도 PNG 27.1MB + PSD (재생성 가능 + 로컬 원본)
- cases 인풋 xls 8.7MB (원본 부류 — 추출 txt는 이미 커밋)
- golden 괴산 `원본.hwpx` 4.9MB (괴산 삽도 2장의 유일 소재 — 삽도 추출 보존 후)
