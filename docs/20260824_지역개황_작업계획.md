## 7. 전국 통계 파서 — 진행 방식

### 7-1. 통계연보 파서와 성격이 다르다 ★

| | 통계연보 (`stats_extract.py`) | 전국 통계 (신규) |
|---|---|---|
| 원천 | **사업마다 바뀐다** (지자체별 발간) | **전 사업이 같은 판** (연 1회 전국) |
| 조회 | 시군 행 × 항목 열 → **셀 하나** | 시군으로 **행 필터** |
| 출력 | 값 (`임야 309.02`) | **표 전체 — 행 수가 사업마다 다르다** |
| 검증 | 값 대조 | **행 수 + 각 행 전 열 대조** |

즉 결과물이 값이 아니라 **표**다. 여기에 그 표에서 파생되는 **서술 문장**이 붙는다
(`총 3개소를 운영 중이며, 사업계획지구가 속한 호저면에는 위치하지 않는 것으로 조사되었다`).

자료가 아니라 이름으로 추론한 것이라 **일반화하면 위험하다** → 면 판정이 불가능하면 `[확인 필요]`.

## 9. 역추적 — 값을 넣으면 자료가 자리를 알려준다 (2026-08-24) ★★

### 9-1. 왜 만들었나

②층 좌표(어느 시트 어느 열)를 **사람이 눈으로 찾으면 사람이 하던 실수를 그대로 물려받는다.**
반대로 가면 된다 — **골든셋 표의 값을 원자료 전체에서 역검색**하면 자료가 자리를 알려준다.

`catalog/trace_stats.py` (검증·분석 전용, 생성 파이프라인에 들어가지 않는다)

```bash
python catalog/trace_stats.py <원자료.xlsx> --values 124604.5 4791.2
#   ✅ 124604.5
#         6. 공공하수처리시설(500톤이상)  행321 열9  ← 유입하수량(500㎥/일이상/미만)/고도
#   ## 시트별 적중 수 — 많이 몰린 곳이 그 표의 출처다
```

값 여러 개가 **같은 시트에 몰리는가**로 출처를 판정한다. 열 이름은 머리글 구간을 찾아
붙이는데, **병합 셀이 `read_only` 에서 `None`** 으로 오므로 왼쪽 값을 끌어 채워야 나온다.

### 9-2. 첫 실행에서 나온 것 — 예상 못 한 자리들 ⚠️

#### ① 원주 골든셋 2.7.1 이 **÷10 되어 있다**

| | 원자료(2023 하수도통계) | 원주 골든셋 |
|---|--:|--:|
| 원주 시설용량 | 156,000 | **15,600** |
| 원주 유입하수량 | 124,604.5 | **12,460.45** |
| 흥업 | 13,000 / 5,679.4 | **1,300 / 567.94** |
| 원주기업도시 | 12,600 / 7,071.1 | **1,260 / 707.11** |
| 문막 | 7,000 / 4,679.8 | **700 / 467.98** |

**8개 값이 전부 정확히 ÷10.** 괴산(8,000↔8,000)·천안(220,000↔220,000)은 **1:1 이다.**
→ **원주 문서만의 오류다.** 인구 36만 도시의 하수처리량이 18,860㎥/일일 수 없다.

⚠️ **원주는 우리 베이스 사업이다.** `regional-overview.slots.md` 에 이미 교정 대상 2건
(구성비 뒤바뀜·캡션 면 이름)을 적어 뒀는데 **세 번째가 나왔다.** 베이스를 뜰 때 같이 고친다.

#### ② 괴산 후평리는 **출처만 갈고 값은 복사했다** ⚠️

| | 출처 표기 | 시설용량 | 유입하수량 | 가동개시일 |
|---|---|--:|--:|---|
| 괴산 금신리 | 2023 하수도통계(2024.11.27.) | 8,000 | 5,822.3 | 2000-07-03 |
| 괴산 후평리 | **2024** 하수도통계(2025.07.31.) | 8,000 | **5,822.3** | 2000-07-03 |

**한 글자도 다르지 않다.** 판을 갈았다면 유입하수량은 바뀌어야 한다.
→ 새 판이 나와도 **표를 다시 뜨지 않고 출처 연도만 고치는 관행**이 있다.
이 파트를 자동화하는 실질 이득이 여기 있다 — 계산이 어려워서가 아니라 **사람이 건너뛰는 자리**다.

#### ③ 그런데 5,822.3 은 **우리가 받은 2023판에도 없다** ⚠️

우리 2023판 괴산 유입하수량은 **4,791.2** 다. 천안(202,494.3)·청주도 마찬가지로 안 나온다.
**시설용량은 맞고 유입하수량만 어긋난다** — 용량은 잘 안 변하고 유입량은 매년 변하니
**골든셋이 인용한 판이 실제로는 더 옛날 판**이라는 뜻이다.

> **같은 "2023 하수도통계"라도 배포본이 여럿이고 값이 다르다.**
> 출처 주석의 연도를 믿고 판을 고르면 값이 안 맞는다. → 판본 식별이 F-1(연도 행)보다 근본적이다.

#### ④ 소재지 상세주소는 **원자료에 없다** — 자동화 불가 ⚠️

원주 골든셋 취수장 소재지 `원주시 귀래면 한치길 11-41` 을 상수도통계 전 시트에서 찾았으나
**어디에도 없다.** 원자료는 `강원특별자치도 원주시` 까지만 준다 (취수·정수 시트 모두).

| 상세주소를 쓴 사업 | 시군까지만 쓴 사업 |
|---|---|
| 원주 · 옥천 · 청주 | 괴산 · 천안 · 평창 |

→ **실무자가 따로 찾은 정보다.** 자동으로는 시군까지만 나온다.
기본값을 원자료 그대로 두고 `[확인 필요]` 로 표시할지, 상세주소를 요구할지는 실무자 판단 (**F-15**).

| 1 | **열 번호** | 일평균취수량 2021판 24 ↔ 2023판 26 | 이름으로 찾는다 ✅ |

| 3 | ⚠️ **헤더 이름 자체가 뒤집힌다** | 지자체 열이 **2021판 `구군` ↔ 2023판 `시군구`** | `시군구$\|구군$` — **이름도 믿을 수 없다** |
| 4 | **집계 행 위치** | 상수도는 `취수장명` 이 `계`, **하수도는 `행정구역명` 이 `소계`** (시설명 자리엔 개소수가 온다) | `제외열` 을 절마다 선언 |

### 11-1. 왜 필요한가 — 오늘 실측이 그대로 근거다

### 11-2. 구현 — `catalog/build_stats_values.py`

```bash
python catalog/build_stats_values.py            # 로컬 원자료 → 값 저장소
python catalog/build_stats_values.py --list     # 무엇이 있고 무엇이 없나
python catalog/build_stats_values.py --show 괴산군   # 판을 가로질러 본다
```

**8개 판 · 합계 1.7MB.** 원자료 90MB 를 열지 않고 값에 닿는다.

### 11-2-1. 커밋 대상을 둘로 갈랐다 ★

기준은 **다시 만들 수 있는가** — `CLAUDE.md` 삽도 대목의 규약을 그대로 적용했다
(*"이미지는 커밋하지 않는다 — 다시 못 만드는 값은 `sheet_georef.json` 실측 좌표와 목록뿐"*).

| | 다시 만들 수 있나 | 처리 |
|---|---|---|
| **값 본체** `stats_values/*.json` | ✅ 원자료 + 코드로 재생성 | **gitignore → NAS 로 공유** |
| **매니페스트** `stats_values.manifest.json` | ❌ **못 만든다** — 어느 판을 썼는가의 기록 | **커밋** (7KB) |

**지금 1.7MB 라 커밋해도 부담은 아니다. 나누는 이유는 크기가 아니라 되돌릴 수 없다는 것이다.**

- 전국 통계는 12종이다 — 판을 3~4개씩 보관하면 **10~20MB**
- JSON 이라 **재빌드하면 전체가 바뀐다** (추출기를 한 줄 고쳐도 8개 파일이 통째로)
- **git 히스토리는 영구적이다** — 나중에 NAS 로 옮겨도 이미 박힌 것은 못 뺀다

지금 나누는 비용은 거의 없고, 나중에 나누는 비용은 못 되돌린다.

매니페스트에는 **값 파일의 sha256 도** 넣었다 — NAS 사본이 우리가 뜬 것과 같은지 대조하려고.

### 11-3. 판 지문(sha256)이 핵심이다 ★

각 파일에 원자료의 **sha256** 을 남긴다. 오늘 배운 것이 이것이다 —
**연도만으로는 판을 가를 수 없다.** 지문이 판을 가르는 유일한 근거다.

```json
"원자료": { "파일명": "★2023 하수도통계(최종).xlsx", "크기": 24239347, "sha256": "…" },
"발행처": { "목록": "https://www.hasudoinfo.or.kr/bbs/lay1/WS10000015/list.do", … },
"추출":   { "일자": "2026-08-24", "도구": "engine/stats_national.py" }
```

발행처 목록 URL 도 같이 넣었다 — **신판 감시가 이 파일에서 출발**한다.

### 11-4. 3층이 4층이 됐다

| 층 | 무엇 | 어디 | 커밋 |
|:--:|---|---|:--:|
| ① | 어느 파일이 어디 있나 | `stats_catalog.json` | ✅ |
| ② | 파일 안 어디에 뭐가 있나 | `stats_national.py` 의 `SOURCES` | ✅ |

| **④** | **꺼낸 값 자체** | **`stats_values/*.json`** | ❌ **NAS** |

**생성은 ④만 보면 된다.** 원자료도 카탈로그도 필요 없다.

`pdftotext -layout` 은 병합된 공원명 칸을 세로 가운데에 놓는다. 그래서

```
다도해해상  전라남도  2,276.21  완도군  582.164
                              진도군  604.369
                              신안군  528.006

치 악 산  강원특별자치도  176.567  횡성군  69.372
```

**줄 위치로는 못 가른다.** → **시도 합계로 검산해 가른다**

### 14-3. 세 번 헛디뎠다 — 전부 같은 뿌리 ⚠️

| # | 증상 | 원인 |
|:-:|---|---|
| 1 | 목차를 본문으로 착각 | 같은 제목이 **목차에도 있다** → 점선(`······`) 없는 쪽을 고른다 |
| 2 | **지리산 블록이 통째로 사라짐** | 첫 공원은 **시도 줄이 공원명 줄보다 먼저** 나오는데 `and blocks` 가드로 막았다. 막으니 뒤 블록이 **전부 한 칸씩 밀렸다** |
| 3 | 한 블록이 어긋나자 **뒤가 전부 붕괴** | 앞에서부터 순서대로 소비하면 실패가 전파된다 → **블록 줄 둘레에서만 국소로 찾는다** |

#### 순서가 의미를 갖는다 ★

`fr()` 는 전역 치환(`AllReplace`)이라 **범위를 못 준다.** 그런데 `원주시` 는 90회 나오고
그중 하나가 **법령표 안의 예시**다 (대기환경보전법 별표10의2 저황유 공급지역
`춘천시, 원주시, 강릉시`). 사업과 무관하므로 바꾸면 안 된다.

```python
("춘천시, 원주시, 강릉시", "@@LAW_LSWR@@"),   # ① 먼저 감싸고
…
("무장리", "{{리}}"), ("호저면", "{{하위행정구역}}"), ("원주시", "{{시군}}"),   # ② 전역 치환
("@@LAW_LSWR@@", "춘천시, 원주시, 강릉시"),    # ③ 되돌린다
```

리 → 면 → 시군 **긴 것부터** 해야 짧은 것에 먹히지 않는다.
