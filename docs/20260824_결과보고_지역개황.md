> **측정 사업**: 천안 화덕리 · **측정일** 2026-08-24 (2차 — 유출 제거 후) · **상세 이력**: `git log`

> **이 문서의 목적**: 세 번째 파트의 첫 생성 결과를 공유하고, 남은 결함의 성격을 구분해 다음 단계를 정하기 위함

## 1. 한눈에

**세 번째 파트가 생성까지 돌아갔습니다.** 표 22개를 자동으로 채우고, 자료가 없는 자리는
`[확인 필요]` 로 비웁니다.

| 파트 | 상태 | 정확도 |
|---|---|---|
| 소음·진동 (7.2.7) | 3개 사업 완료 | 천안 **94.8%** · 괴산 59.0% · 청양 50.0% |
| 대기질 (7.2.2) | 1개 사업 완료 | 평창 **61.6%** |
| **지역개황 (제2장)** | **1개 사업 생성·검증** | **천안 65.2%** (1,734줄 중 1,131줄 일치) |

```
정답 1,734줄
 ├ 일치           1,131줄  65.2%
 └ 불일치           603줄
     ├ [확인 필요]로 비움   295줄  ← 자료가 없어 정직하게 비운 자리
     └ 원주 값 잔존         100줄  ← 남은 결함 (1차 160줄 → 38% 감소)
        (나머지는 줄 분할·표기 차이)
```

### ⚠️ 숫자가 내려간 것이 개선입니다

1차 65.8% → 2차 **65.2%** 로 0.6%p 내렸습니다. **원주 문장을 지웠기 때문**입니다.

베이스 문서의 서술 문단에 원주 내용이 남아 있었고, 그중 일부가 천안 정답과
**우연히 겹쳤습니다** (예: `유하거리 10km 이내에 수변구역과 상수원보호구역은…`).
문단을 통째로 `[확인 필요]` 로 바꾸니 그 줄까지 사라졌습니다.

대신 **천안 보고서에서 원주 고유 지명이 전부 사라졌습니다** —
치악산 · 원주천 · 섬강 · 귀래 · 문막 · 소초 · 흥업 · 무장 **모두 0건**.

> 실무자 입장에서 **빈칸은 채우면 되지만, 그럴듯하게 틀린 문장은 찾지 못합니다.**
> `common.md` 환각 금지 원칙이고, 소음·진동에서 정한 기준과 같습니다.

> **숫자를 다른 파트와 나란히 놓고 비교하면 안 됩니다.** 소음·진동은 "계산을 재현"하는
> 문제였고, 지역개황은 **"외부 통계를 조달"** 하는 문제입니다. 성격이 다릅니다 (§3).

## 2. 이 파트가 왜 다른가

앞의 두 파트는 **측정값을 계산**했습니다. 인풋에 값이 있고, 규칙대로 계산하면 답이 나옵니다.

지역개황은 그렇지 않습니다. 이런 표가 문서를 채웁니다.

```
천안시 및 동면의 지목별 토지이용현황
구 분   계      임야     답      하천    전      도로    과수원  대지   기타
천안시  636.16  308.34  92.22   15.51  51.61   27.87   15.59  40.38  84.64
```

이 숫자들은 사업개요에도, 환경질측정 보고서에도 **없습니다.** 실무자가 `천안시 통계연보`
를 열어 옮겨 적은 값입니다. 미팅에서 "손이 많이 간다"고 하신 지점이 정확히 이것입니다.

**그래서 이 파트의 성패는 계산이 아니라 자료 조달에 달려 있습니다.**

## 3. 자료가 어디까지 준비돼 있었나

Mac 세션에서 통계 추출 체계를 먼저 만들어 뒀습니다 (`engine/stats_extract.py` 외).
천안은 통계연보 원자료를 가진 사업이라 **24개 통계 항목 중 18개가 vars 에 채워진 상태**로
이번 생성에 들어갔습니다.

| 통계 항목 | 상태 |
|---|:--:|
| 값 있음 | **18** |
| 빈 목록 = 지정 없음 | 5 |
| 미확보 | 1 (지리적 좌표 — 통계연보 **엑셀 편에 없고 책자 본문에만** 있습니다) |

즉 이번 측정은 **"자료가 있을 때 문서로 옮기는 일"이 얼마나 되는가**를 잰 것입니다.

### 4-3. 남은 결함 — 셋으로 나뉩니다

**① 표를 넣지 못한다 (가장 심각)**

천안에는 소각시설이 2개소 있고 **그 자료가 vars 에 있습니다.** 그런데 베이스 문서(원주)에는
소각시설 표가 없어서 넣을 자리가 없었습니다. 더 나쁜 것은 문장입니다.

```
정답 : 천안시는 2개소의 공공소각시설을 운영 중에 있으며, 2023년 154,691.5톤을 처리…
생성 : 천안시는 … 상 소각시설을 운영하지 않는 것으로 조사되었다.     ← 우리가 가진 자료와 모순
```

빈칸이 아니라 **틀린 문장**이 나갑니다. 자료가 없어 비우는 것과는 성격이 다릅니다.

**② 표 서식이 사업마다 다르다**

산업단지 표의 열 구성이 아예 다릅니다.

| | 열 |
|---|---|
| 원주(베이스) | 구분 · 단지명 · 소재지 · 면적(천㎡) · 조성상태 · 분양상태 |
| 천안(정답) | 구분 · 위 치 · 지정일 · 조성현황 |

값을 정확히 넣어도 표 모양이 달라 일치율이 10% 로 나옵니다. **채우기의 문제가 아니라
서식의 문제**입니다.

**③ ~~절 도입 문장이 원주 문장 그대로다~~ → ✅ 해소 (2차)**

1차에서 가장 컸던 결함입니다. 토큰이 문단의 **첫 구절만** 덮고 있었습니다.

```
{{시군_개황}}, 동쪽은 영월군·평창군, … 치악산 비로봉을 최고봉으로 … 원주천은 …
└─ 여기까지만 치환                    └─ 이 뒤 200자가 원주 서술 그대로
```

빈칸 명세(A-5)는 원래 **"7줄 전체"** 가 의도였는데 치환 문자열이 짧았습니다.
문단 전체로 확장하고, 같은 문제였던 `2.8.3 수 계` 서술도 새 토큰(`{{수계_서술}}`)으로
뽑았습니다. 토큰 28 → **29종**.

함께 막은 자리 — 지정 없는 표 삭제(자연공원·산림유전자원) · 겨울철 조류 표와 문장 ·
폐수 지역지정·설치제한지역 표 · 하천일람 기본값 · 하수 표 행 오프셋.

원주 값 잔존 **160 → 100줄**. 남은 100줄의 내역은 표 셀 56 · 본문·캡션 22 ·
출처 판 미갱신 19 · 주석 3 이며, **원주 고유 지명은 0건**입니다.

> 출처 판 19줄은 지금 고칠 수 없습니다. 고시 판(`대기환경보전법 시행령 별표10의2` 등)이
> 베이스에 원주 기준으로 박혀 있는데 **vars 에 대체할 값이 없습니다.** 토큰으로 뚫으면
> 전부 `[확인 필요]` 가 되는데, 그럴듯한 현재 판보다 나은지는 판단이 필요합니다 (§6).

### 4-4. 육안 확인에서만 잡힌 것 ★

PDF 로 바꿔 페이지를 직접 봤습니다 (`to_pdf.py` → `pypdfium2`). **텍스트 대조로는
절대 안 잡히는 결함 두 개**가 나왔습니다.

**① 삽도가 통째로 원주 것이었습니다 → ✅ 해결**

본문 텍스트에서는 원주 하천 이름을 다 지웠는데, **그림 안에는 그대로 남아 있었습니다.**

```
수계흐름모식도 :  사업계획지구 → 섬강(국가) → 한강(국가)   총 유하거리 34.54km
                  ↑ 전부 원주 값. 천안과 무관합니다.
수계도         :  원주 지역 지형도
```

게다가 삽도 6종만이 아니라 **원주 정온시설 현장사진 8장**(축사·민가 실사진)까지
합쳐 **14장**이 실려 나가고 있었습니다.

삽도는 HWPX 안의 이미지(BinData)라 텍스트 추출에 안 잡힙니다. 그래서 정확도 65.2%
에도, 빈칸 잔여 검사에도 걸리지 않았습니다. **PDF 를 눈으로 봐야만 보이는 결함**이었습니다.

**조치 — 비우기 + 재발 방지 검사**

| 함수 | 하는 일 |
|---|---|
| `blank_figures()` | 베이스와 바이트가 같은 그림을 **`[삽도 필요]` 판으로 갈아 끼운다** |
| `check_stale_figures()` | 저장할 때마다 검사해 **베이스 그림이 남아 있으면 경고**한다 |

천안 재생성 결과 **20장이 비워지고 잔존 검사 통과**했습니다 (PDF 육안 확인 완료).

> ⚠️ **여기서 한 번 더 틀렸습니다.** 처음 만든 수정과 검사가 **같은 매핑**을 써서,
> 엉뚱한 그림 13장을 지우고도 `잔존 없음 ✅` 을 냈습니다. PDF 를 보고서야 잡혔습니다.
> 검사를 **바이트+크기**라는 다른 근거로 바꾸자, 이번엔 이름 규칙의 결함
> (`원주시 행정구역` 지도가 살아남음)을 **자동으로** 잡아냈습니다.
>
> 최종 판정은 두 근거의 **합집합**입니다 — 이름이 있거나(원본 파일 유래) 300KB 이상.
> 어느 하나만 믿었을 때 각각 새는 것을 실측으로 확인했습니다.
이제 육안 확인 없이도 같은 결함이 자동으로 잡힙니다.

> `slots.md` §D 가 원래 "자리만 남기고 `[삽도 필요]` 로 표시한다" 고 정해둔 방식입니다.
> 명세는 있었고 구현이 빠져 있었습니다.

**② 저황유 공급지역 표가 `강원` 행입니다**

법령표라 손대지 않았는데, 이 표는 **시·도별로 행이 다릅니다.** 천안은 충남이어야 하는데
원주 기준 `강원 / 춘천시, 원주시, 강릉시` 가 남았습니다. 법령표라고 다 고정은 아닙니다.

### 4-5. 정상 확인된 것

- **레이아웃이 깨지지 않았습니다.** 표 27행 확장·표 삭제 후에도 쪽 나눔과 표 잘림이 정상입니다
- **`[확인 필요]` 빨간 글자가 표 안에서도 잘 보입니다.** 295건 중 286건(96.9%) 적용

## 5. 과정에서 얻은 것 — 한글 표 편집의 함정 4종

이번 작업의 절반은 **한글 API 가 조용히 틀리는 자리**를 찾는 데 들어갔습니다.
넷 다 **에러가 나지 않아** 결과 문서를 열어보기 전까지 알 수 없습니다.
전부 `.claude/rules/hwpx.md` 에 재현 조건과 판별법까지 적었습니다.

| 함정 | 증상 | 해법 |
|---|---|---|
| `gen_py` 캐시 손상 | `Open()` 이 27분간 멎음 | 캐시 삭제. **CPU 가 분당 1초면 막힌 것** |
| 앵커 중복 | 값이 **다른 표에** 박히고 로그는 정상 | 원본에서 출현 횟수를 세고 쓴다 |
| 셀이 문단으로 갈림 | `유입하수량(㎥/일)` 이 실제로는 두 문단 | 앵커를 **문단 단위**로 고른다 |
| 세로 병합 | 행마다 칸 수가 달라 열이 밀린다 | **`KeyIndicator()` 로 셀 주소를 읽는다** ↓ |

### 병합 표를 푼 방법

`hwp.KeyIndicator()` 의 마지막 항목이 셀 주소를 줍니다.

```
(True, 3, 1, 28, 1, 1, 9, 0, '(E1): 문자 입력')
```

표를 걸으며 찍어보면 병합 동작이 그대로 보입니다.

```
행2:  A2 B2 C2 D2 E2 F2
행3:  A2 ← 병합 칸을 다시 지난다   B3 C3 D3 E3 F3
행4:  A2                          B4 C4 D4 E4 F4
```

**병합 칸이 자기 원래 행 번호를 알려줍니다.** 그래서 칸을 세지 않고, 행을 걸으며
`행번호 == 목표행` 인 칸에만 쓰면 병합과 무관하게 정확히 맞습니다.

실측해 보니 **같은 시각적 열이 행마다 다른 문자를 씁니다.** 용도지역 표는
3행이 `C D E G I J L N O P Q`, 4행이 `C D F H I K M N O P Q` 입니다.
짐작으로는 맞힐 수 없고, 프로브로 한 번 뜨면 확정됩니다.

### ① 표 삽입 — 지금 가장 큰 결함

소각시설처럼 **자료는 있는데 베이스에 표가 없는** 경우입니다. 절 삽입 기능은 지금 보류
상태인데(할 일 2), 지역개황에서 실제 손해가 확인됐습니다. 우선순위를 올릴지 판단이 필요합니다.

### ② 표 서식 변이 — 실무 확인 사항

산업단지 표처럼 **열 구성이 사업마다 다른** 표를 어떻게 할지입니다.

- 회사 표준 서식이 있다면 그것으로 통일 → 우리가 그 서식으로 베이스를 만듭니다
- 없다면 사업마다 다른 채로 두는 것이 맞는지

지목별 토지이용 표의 열 순서도 골든셋 8건이 **3:3 으로 갈립니다** (면적 큰 순 ↔ 지목 코드순).

### ③ 절 도입 문장 — 어디까지 자동화할지

미팅에서 말씀하신 **"단락 방향성"** 이 바로 이 문제입니다. 지금은 지명만 치환되고 서술은
원주 문장이 남습니다. 문장을 통째로 생성할지, 조건에 따라 고르게 할지, 아니면
`[확인 필요]` 로 비워 실무자가 쓰게 할지 — 방향을 정해야 합니다.

### ④ 삽도 삽입 — 비우기는 됐고, 이제 채우는 일이 남았습니다

원주 그림이 실려 나가던 문제는 해결했습니다 (§4-4 ①). 지금은 `[삽도 필요]` 로 비어 있습니다.

다음은 **천안 삽도를 실제로 만들어 넣는 것**입니다. 자동 생성 도구는 이미 있고
정답 근접 판정도 받았는데(`figure_overlay.py` 외), **hwp 문서에 넣는 것만 미검증**입니다
(지시서 §5-2). 우선순위 판단이 필요합니다.

### ⑤ 지리적 좌표 — 통계연보 엑셀에 없습니다

시군 극점 좌표는 통계연보 **책자 본문에만** 있고 엑셀 배포판에는 없습니다.
실무자가 입력하는 항목으로 둘지, 다른 출처를 찾을지 확인이 필요합니다.
