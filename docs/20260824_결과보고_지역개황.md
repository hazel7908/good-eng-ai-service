## 1. 한눈에

**세 번째 파트가 생성까지 돌아갔습니다.** 표 22개를 자동으로 채우고, 자료가 없는 자리는
`[확인 필요]` 로 비웁니다.

| 파트 | 상태 | 정확도 |
|---|---|---|
| 소음·진동 (7.2.7) | 3개 사업 완료 | 천안 **94.8%** · 괴산 59.0% · 청양 50.0% |
| 대기질 (7.2.2) | 1개 사업 완료 | 평창 **61.6%** |
| **지역개황 (제2장)** | **1개 사업 생성·검증** | **천안 65.8%** (1,734줄 중 1,141줄 일치) |

```
정답 1,734줄
 ├ 일치           1,141줄  65.8%
 └ 불일치           593줄
     ├ [확인 필요]로 비움   258줄  ← 자료가 없어 정직하게 비운 자리
     └ 원주 값 잔존         160줄  ← 실제 결함
        (나머지는 줄 분할·표기 차이)
```

> **숫자를 다른 파트와 나란히 놓고 비교하면 안 됩니다.** 소음·진동은 "계산을 재현"하는
> 문제였고, 지역개황은 **"외부 통계를 조달"** 하는 문제입니다. 성격이 다릅니다 (§3).

## 2. 이 파트가 왜 다른가

앞의 두 파트는 **측정값을 계산**했습니다. 인풋에 값이 있고, 규칙대로 계산하면 답이 나옵니다.

지역개황은 그렇지 않습니다. 이런 표가 문서를 채웁니다.

```
천안시 및 동면의 지목별 토지이용현황
구 분   계      임야     답      하천    전      도로    과수원  대지   기타
천안시  636.16  308.34  92.22   15.51  51.61   27.87   15.59  40.38  84.64
```

이 숫자들은 사업개요에도, 환경질측정 보고서에도 **없습니다.** 실무자가 `천안시 통계연보`
를 열어 옮겨 적은 값입니다. 미팅에서 "손이 많이 간다"고 하신 지점이 정확히 이것입니다.

**그래서 이 파트의 성패는 계산이 아니라 자료 조달에 달려 있습니다.**

---

## 3. 자료가 어디까지 준비돼 있었나

Mac 세션에서 통계 추출 체계를 먼저 만들어 뒀습니다 (`engine/stats_extract.py` 외).
천안은 통계연보 원자료를 가진 사업이라 **24개 통계 항목 중 18개가 vars 에 채워진 상태**로
이번 생성에 들어갔습니다.

| 통계 항목 | 상태 |
|---|:--:|
| 값 있음 | **18** |
| 빈 목록 = 지정 없음 | 5 |
| 미확보 | 1 (지리적 좌표 — 통계연보 **엑셀 편에 없고 책자 본문에만** 있습니다) |

즉 이번 측정은 **"자료가 있을 때 문서로 옮기는 일"이 얼마나 되는가**를 잰 것입니다.

### 4-3. 남은 결함 — 셋으로 나뉩니다

**① 표를 넣지 못한다 (가장 심각)**

천안에는 소각시설이 2개소 있고 **그 자료가 vars 에 있습니다.** 그런데 베이스 문서(원주)에는
소각시설 표가 없어서 넣을 자리가 없었습니다. 더 나쁜 것은 문장입니다.

```
정답 : 천안시는 2개소의 공공소각시설을 운영 중에 있으며, 2023년 154,691.5톤을 처리…
생성 : 천안시는 … 상 소각시설을 운영하지 않는 것으로 조사되었다.     ← 우리가 가진 자료와 모순
```

빈칸이 아니라 **틀린 문장**이 나갑니다. 자료가 없어 비우는 것과는 성격이 다릅니다.

**② 표 서식이 사업마다 다르다**

산업단지 표의 열 구성이 아예 다릅니다.

| | 열 |
|---|---|
| 원주(베이스) | 구분 · 단지명 · 소재지 · 면적(천㎡) · 조성상태 · 분양상태 |
| 천안(정답) | 구분 · 위 치 · 지정일 · 조성현황 |

값을 정확히 넣어도 표 모양이 달라 일치율이 10% 로 나옵니다. **채우기의 문제가 아니라
서식의 문제**입니다.

**③ 절 도입 문장이 원주 문장 그대로다**

빈칸 명세(§A)는 토큰 28종을 다루는데, 각 절의 도입 서술은 대부분 대상이 아닙니다.
그래서 지명만 바뀐 원주 문장이 남습니다.

```
생성 : 사업계획지구와 인접한 구거를 따라 약 1.93km 유하하여 섬강(국가)에 합류되며…
       ↑ 섬강은 원주의 하천입니다. 천안과 무관합니다.
```

원주 값 잔존 **160줄**의 내역은 이렇습니다 — 표 셀 91 · 캡션·머리행 45 · 출처 판 미갱신 21 · 주석 3.

## 5. 과정에서 얻은 것 — 한글 표 편집의 함정 4종

이번 작업의 절반은 **한글 API 가 조용히 틀리는 자리**를 찾는 데 들어갔습니다.
넷 다 **에러가 나지 않아** 결과 문서를 열어보기 전까지 알 수 없습니다.
전부 `.claude/rules/hwpx.md` 에 재현 조건과 판별법까지 적었습니다.

| 함정 | 증상 | 해법 |
|---|---|---|
| `gen_py` 캐시 손상 | `Open()` 이 27분간 멎음 | 캐시 삭제. **CPU 가 분당 1초면 막힌 것** |
| 앵커 중복 | 값이 **다른 표에** 박히고 로그는 정상 | 원본에서 출현 횟수를 세고 쓴다 |
| 셀이 문단으로 갈림 | `유입하수량(㎥/일)` 이 실제로는 두 문단 | 앵커를 **문단 단위**로 고른다 |
| 세로 병합 | 행마다 칸 수가 달라 열이 밀린다 | **`KeyIndicator()` 로 셀 주소를 읽는다** ↓ |

### 병합 표를 푼 방법

`hwp.KeyIndicator()` 의 마지막 항목이 셀 주소를 줍니다.

```
(True, 3, 1, 28, 1, 1, 9, 0, '(E1): 문자 입력')
```

표를 걸으며 찍어보면 병합 동작이 그대로 보입니다.

```
행2:  A2 B2 C2 D2 E2 F2
행3:  A2 ← 병합 칸을 다시 지난다   B3 C3 D3 E3 F3
행4:  A2                          B4 C4 D4 E4 F4
```

**병합 칸이 자기 원래 행 번호를 알려줍니다.** 그래서 칸을 세지 않고, 행을 걸으며
`행번호 == 목표행` 인 칸에만 쓰면 병합과 무관하게 정확히 맞습니다.

실측해 보니 **같은 시각적 열이 행마다 다른 문자를 씁니다.** 용도지역 표는
3행이 `C D E G I J L N O P Q`, 4행이 `C D F H I K M N O P Q` 입니다.
짐작으로는 맞힐 수 없고, 프로브로 한 번 뜨면 확정됩니다.

## 6. 다음 단계 — 논의하고 싶은 것

### ① 표 삽입 — 지금 가장 큰 결함

소각시설처럼 **자료는 있는데 베이스에 표가 없는** 경우입니다. 절 삽입 기능은 지금 보류
상태인데(할 일 2), 지역개황에서 실제 손해가 확인됐습니다. 우선순위를 올릴지 판단이 필요합니다.

### ② 표 서식 변이 — 실무 확인 사항

산업단지 표처럼 **열 구성이 사업마다 다른** 표를 어떻게 할지입니다.

- 회사 표준 서식이 있다면 그것으로 통일 → 우리가 그 서식으로 베이스를 만듭니다
- 없다면 사업마다 다른 채로 두는 것이 맞는지

지목별 토지이용 표의 열 순서도 골든셋 8건이 **3:3 으로 갈립니다** (면적 큰 순 ↔ 지목 코드순).

### ③ 절 도입 문장 — 어디까지 자동화할지

미팅에서 말씀하신 **"단락 방향성"** 이 바로 이 문제입니다. 지금은 지명만 치환되고 서술은
원주 문장이 남습니다. 문장을 통째로 생성할지, 조건에 따라 고르게 할지, 아니면
`[확인 필요]` 로 비워 실무자가 쓰게 할지 — 방향을 정해야 합니다.

### ④ 지리적 좌표 — 통계연보 엑셀에 없습니다

시군 극점 좌표는 통계연보 **책자 본문에만** 있고 엑셀 배포판에는 없습니다.
실무자가 입력하는 항목으로 둘지, 다른 출처를 찾을지 확인이 필요합니다.
