# 미팅 결과 — 2026-08-13 (컨택 포인트)

> 클라이언트 요청 5건과 우리의 대응 방향. 실행 항목은 `CLAUDE.md` 다음 할 일에 반영됨.

## 1. 단락 방향성 — "빈칸 채우기를 넘어, 수치에 따라 단락 전체가 달라져야 한다"

**요청 요지**: 앞선 수치·조건에 따라 각 단락의 서술 방향 자체가 바뀌는 경우가 있다.
단락별로 "여기는 무엇을 쓰는 자리인지"를 파악해 자동 생성하거나, 어려우면
**생성 방향이라도 사용자에게 제안**해달라.

**우리 해석**: 청양에서 이미 관측한 "빈칸 치환으로 도달 불가 영역"의 클라이언트 버전.
일부는 이미 구현돼 있다 (상회 여부 → 저감 구조 분기, 인용 여부 → 문구 6곳 연동).
확장 방향 두 갈래:

- **rule 장르 ⑤(조건부 문구)를 단락 단위로 승격** — 골든셋에서 "조건 → 단락 방향" 매핑 도출
- **fill-report 에 "단락 방향 제안" 절 추가** — 자동 확정이 안 되는 단락은 조건과 후보
  방향을 제시 (`[실무자 확인]` 체계의 단락판). 절 삽입 보류(할 일 2)와 연결됨

**시점**: 지역개황 파트에서 실전 소재로 검토 → 설계. 전 파트 공통 체계는 그 뒤.

## 2. 다음 파트 = 지역 개황(0200) ★ 확정

**요청 요지**: 외부 검색으로 지역·전국 **최신 통계**를 채우는 일이 손이 많이 간다.
통계 자료가 NAS 어딘가 있지만 비체계적 — **중요 통계의 체계적 관리 방법**도 찾아달라.

**우리 해석**: "실무 부담이 큰 파트" 질문의 답. 우리 파이프라인과의 겹이득 —
지역개황은 rule §2-4 가 지목한 **PP 표 출처 1순위**라, 이 파트가 자동화되면
소음진동·대기질의 인풋 확보도 같이 풀린다. 새 과제 유형: **외부 데이터 소싱**
(통계청 KOSIS·지자체 통계연보 등) — 기존 파트들(계산 재현)과 다른 축.

**착수 계획**: ① 0200 골든셋 확보 (전수 234건 중 최근 사업 선별) → `/distill-golden`
② 변수의 출처 분석 — 어떤 통계를 어디서 가져오는지 (외부 vs NAS vs 인풋)
③ 통계 관리 체계 설계 — 카탈로그 v2 와 연계 검토

## 3. 표준 인풋 리스트 — 확대 완료 후 일괄 정리

**요청 요지**: 전 파트 확대가 끝나면 "사용자가 기본 제공해야 하는 인풋 리스트"가
나올 것 — 나중에 한 번에 정리해서 요구하는 방식으로.

**우리 대응**: 동의. 각 파트 rule 의 변수표(분류 O/계산/삽도△/X)가 이미 그 원천이라,
확대가 끝나면 rule 들에서 **기계적으로 집계 가능**하다. 지금은 파트마다 vars
`_확인필요` 에 쌓아두는 것으로 충분.

## 4. `[확인 필요]` 빨간색 표시

**요청 요지**: 자동 생성 안 된 자리를 사용자가 찾기 쉽게 빨간 글자로.

**우리 대응**: 가능 — 한글 API `CharShape` 로 저장 직전 `[확인 필요]`/`[모델링 필요]`
전 항목에 색 적용. Windows 소작업 (generate.py 마무리 단계에 추가).

## 5. 삽도 제작 — 지도 위 글자·구역·화살표 (지역개황 유형)

**요청 요지**: 지역개황의 삽도처럼 지도 이미지에 라벨·유수 방향 화살표·계획대상지
마커를 얹는 것도 가능한지. (예시 이미지 확인: 유역도 — 하천 흐름 화살표 + 지명
글자 + 계획대상지 표적 마커)

**우리 대응**: 두 층으로 나뉜다 —
- **그리기 자체는 가능**: 베이스 지도 이미지 위 오버레이(텍스트·마커·화살표)는
  Pillow 로 합성 가능. 골든셋 삽도에서 스타일(글꼴·마커 모양) 추출
- **어디에 그릴지가 관건**: 마커·화살표의 위치는 좌표 데이터가 필요 — 사용자가
  베이스 지도에 좌표만 찍어주면 나머지를 자동화하는 반자동이 현실적 시작점
- 지역개황 골든셋 분석 때 삽도 유형·제작 패턴을 함께 조사
