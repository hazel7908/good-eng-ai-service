# 앵커가 없어도 게이트는 초록이다 — `anchor_check` 신설

2026-09-08 · Windows 세션

## 1. 어떻게 드러났나

`topo-geology` 재생성이 `WARNING: 앵커 '공내지하수위' 못 찾음` 을 냈다. 표를 열어 보니
그 말은 **표의 캡션**이었다 — 칸 안이 아니다. `find_in_table` 은 표 밖을 보지 않는다.

대체 앵커로 머리 셀 `지반고EL(+)m` 을 골랐는데 **이것도 안 잡혔다.** 그 칸이

```
문단 2개 · 런 2개 → ['지반고', 'EL(+)m']
```

**두 문단**이라 한글 찾기가 경계를 못 넘는다. 평면화한 추출 텍스트에서는 한 줄로 보인다 —
CLAUDE.md §6 의 *"평면화된 추출 텍스트로 표 구조를 세면 안 된다"* 와 같은 뿌리다.

⚠️ **앵커가 안 잡히면 `blank_tables` 는 0을 돌려주고 그 표는 기준 사업 값 그대로 나간다.**
생성은 성공으로 끝나고 `smoke_check` 도 통과한다. WARNING 한 줄이 유일한 흔적인데,
배치 로그에서는 스크롤에 묻힌다.

## 2. 도구 — `engine/anchor_check.py`

한글 없이 **HWPX XML 만 읽어** BLANK 앵커 전수를 정적 검사한다. 문단 단위로 텍스트를
재조립하고, `<hp:tc>` **깊이**로 표 안 여부를 판정한다(비탐욕 매칭은 중첩표에서
바깥 칸이 안쪽 닫힘에 끊겨 뒷부분을 "표 밖"으로 둔갑시킨다 — 실제로 겪었다).

못 찾는 이유를 셋으로 갈라 말한다:

| 판정 | 뜻 |
|---|---|
| `표 밖(캡션·본문)` | 글자는 있는데 칸 안이 아니다 — `find_in_table` 이 안 본다 |
| `문단 경계로 쪼개짐` | 칸 안이지만 줄바꿈으로 갈렸다 — 찾기가 못 넘는다 |
| `베이스에 없음` | 그런 글자가 아예 없다 — 앵커를 다른 문서에서 베꼈다는 뜻 |

## 3. 첫 가동 — 39파트 259앵커 중 **11개가 죽어 있었다**

| 파트 | 앵커 | 판정 | 조치 |
|---|---|---|---|
| env-impact/land-use | `지목별 토지이용현황` `편입토지면적` `소유자별 토지이용현황` | 표 밖 | → `구,대,도,목,천` · `개발행위대상` · `기획재정부` |
| env-impact/landscape | `경관분석` | 표 밖 | → `예비조망점 선정` |
| env-impact/noise-vib | `목표소음기준` | 쪼개짐 (`목표소음`/`기준(dB(A))`) | → `목표소음` |
| env-impact/resource-cycle | `처리대상인원` | 쪼개짐 (`정화조 처리대상`/`인원(인)`) | → `인원산정식` |
| strategic-env/plan-overview | `시설물 설치계획` | 표 밖 | → `설치목적` |
| env-impact/noise-vib | `주간평균` | 베이스에 없음 | **삭제 — 재식별 필요** |
| env-impact/resource-cycle | `1일1인당` `잡품비` | 베이스에 없음 | 〃 |
| strategic-env/plan-overview | `사업비` | 베이스에 없음 | 〃 |

지금은 **못 찾는 앵커 0**. 대체 앵커는 전부 *표 안 · 한 문단 · 출현 1~2회* 로 실측 확인했다.

⚠️ **없는 앵커 4개는 지우기만 했다.** 그 표들은 여전히 기준 사업 값이 남아 있다 —
비슷해 보이는 표를 짐작으로 비우면 법령표를 지울 수 있고, 그쪽이 더 나쁘다.
어느 표를 노렸던 건지 되짚어야 한다(BLANK 목록은 산출물 머리 셀 실측으로 만들었는데
그 실측이 다른 파트 것과 섞인 흔적이다).

## 4. 함께 정리한 것

- **BLANK 중복 앵커 5건** — air-quality·greenhouse-gas·regional-overview·water-quality.
  같은 표를 두 번 훑어 시간만 쓴다. 뒤엣것을 지웠다(앞 항목이 문맥 주석과 짝지어 있다)
- `blank_tables` 는 `limit` 만큼 다시 찾는다 — 라벨이 여러 번 나오는 표는 limit 을 올려야
  전부 비워진다(water-quality 4 · greenhouse-gas 5 · topo-geology 1 상향)

## 5. 🚨 한글 COM 이 또 멈췄다 — 재부팅 필요

세 파트가 연달아 `Open()` 에서 매달렸다. **최소 재현**(Dispatch 1.3초 → `Open()` 무한)
으로 문서·핸들러 문제가 아님을 확인했다. `hwp_util` 주석에 이미 적혀 있던 증상 그대로다:
*"잔여 한글 프로세스가 남아 있으면 `Open()` 이 10분+ 멈춘다 — CPU 는 거의 0인데 안 끝난다."*

- 조치: `open_hwp` 가 **경고만 하던 것을 기다림+즉시 실패로** 바꿨다(최대 30초 대기 →
  그래도 남아 있으면 매달리는 대신 종료). 17분 뒤에 아는 것보다 낫다
- ⚠️ **`Hwp.exe` 강제 종료를 파트마다 반복하면 누적된다.** 재부팅 직후 3파트는 정상이었고
  그 뒤 전부 매달렸다. 배치에서 `taskkill` 상용을 줄이고, 실패 시에만 쓸 것
- 재부팅 후 재생성 대기: `env-impact` 의 topo-geology · greenhouse-gas · water-quality
  (앵커 수정분 미반영 — 산출물은 커밋본으로 되돌려 뒀다)
