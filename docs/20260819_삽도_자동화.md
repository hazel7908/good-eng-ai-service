# 지역개황 삽도 자동화 — 조사·구현·검증 (2026-08-19~20)

> 2026-08-13 미팅 요청 — *"지역개황에서 이미지에 글자를 쓰거나 구역 표시하는 것 같은 게 있는데
> 이런 것도 가능한지"* — 에서 시작한 작업의 전체 기록.
>
> 코드: `engine/map_fetch.py`(지도 받기·지오코딩) · `engine/figure_overlay.py`(그리기) ·
> `engine/psd_base.py`(옛 PSD 에서 베이스 추출)

---

## 요약 — 한 장으로

**사업 주소 한 줄이면 삽도가 나온다.**

```
"충청북도 괴산군 청안면 금신리 155-1"
   → 지오코딩 → 좌표 (14208655.63, 4406482.02)
   → 축척 자동 선택 → 지형도 768×768 취득
   → 정온시설 표를 마커로 배치 → 범례·축척·방위 → 완성 삽도(JPG)
```

사람이 넣는 것은 **주소 한 줄과 정온시설 표**뿐이다. 좌표·축척·타일 좌표·마커 위치·
범례 배치·축척 라벨은 전부 계산된다.

| 삽도 6종 | 자동화 | 남은 것 |
|---|:--:|---|
| 정온시설 및 개발시설 현황 (2.9-1) | **● 완전** | — |
| 지역개황도 (2.10-1) | **● 완전** | — |
| 수계흐름모식도 (2.8-3) | **● 완전** | — |
| 수계도·유역도 (2.8-4) | ◑ 거의 | 하천 흐름 경로 입력(반자동) |
| 생태·자연도 (2.8-1) | ◐ 경로 확인 | **공공데이터포털 키**(자동승인) |
| 식생보전등급도 (2.8-2) | ✗ 대상 아님 | 동식물상 조사 산출물 |

**3종 완전 자동 · 1종 거의 · 1종 키만 받으면 됨 · 1종은 우리 몫이 아님.**

## 1. 지역개황의 삽도는 어떻게 구성되나

### 1-1. 캡션이 붙은 삽도는 6종 (골든셋 8건 전수, 8/8 동일)

| 그림 번호 | 이름 | 무엇을 보이나 |
|---|---|---|
| 2.8-1 | 생태·자연도 | 사업지 일대의 생태 등급(1~3등급·별도관리지역) |
| 2.8-2 | 식생보전등급도 | 식생보전 Ⅰ~Ⅴ등급 분포 |
| 2.8-3 | 수계흐름모식도 | 물이 어디로 흘러 어느 본류에 합류하는지 |
| 2.8-4 | 수계도(유역도) | 하천 흐름과 지정구역을 지도 위에 |
| **2.9-1** | **정온시설 및 개발시설 현황** | 사업지 주변 민가·축사·마을의 방향과 거리 |
| 2.10-1 | 지역개황도 | 사업지 위치를 넓은 지도 위에 |

> ⚠️ 처음에 **5종으로 세었다.** 그림 캡션이 청주(PDF 유래) 텍스트에서만 `<그림 N-M>` 형태로
> 살아 있고, hwp 추출본에서는 표 캡션과 구분되지 않아 **정온시설 분포도를 놓쳤다.**

### 1-2. 파일 개수는 그보다 많다 — 사업당 24~37장

hwp 안의 이미지를 전수로 세면 8건 합 **245장**이다.

| 유형 | 8건 합계 | 사업당 | 자동화 |
|---|--:|---|:--:|
| 지도·도면류 | 81 | 3~20 | 위 6종 + 표·법령 캡처 등 부속 |
| **현장사진** (6960×4640 DSLR 원본) | 55 | 1~14 | ✗ **현장 촬영이라 대상 아님** |
| 기호·범례 조각 | 109 | 7~16 | 문서 서식의 일부 |

현장사진은 실무자가 현장에 나가 찍는다. 다만 **정온시설 사진이라 정온시설 표와 짝이 맞아야**
하고, 그 표는 우리가 다룬다.

### 1-3. 삽도 한 장은 3층이다

골든셋 PSD 를 열어 확인한 구조다. **실무자가 이미 이렇게 작업하고 있었다.**

| 층 | 내용 | 누가 |
|:--:|---|---|
| **① 베이스 지도** | 지형도 · 생태자연도 · 국토환경성평가지도 · 위성사진 | 외부에서 받아 온다 |
| **② 오버레이** | 사업지 경계 · 라벨 · 표적 마커 · 구역 채색 · 흐름 화살표 · 지명 · **정온시설 분포** | 우리가 그린다 |
| **③ 장식** | 범례 · 축척 막대 · 방위표 | 우리가 그린다 (고정 서식) |

근거 — 괴산 `국토환경성평가지도.psd` (문서 700×450, 레이어 14):

```
1813×799  레이어 2        ← ① 베이스 (웹 지도 캡처)
  74×95   경계            ← ② 사업지 경계
 107×18   사업계획지구      ← ② 라벨
 193×82   범례 · 213×17 축척 · 66×61 방위   ← ③ 장식
```

### 1-4. 실무자는 포토샵으로 만들고 있었다

```
웹에서 지도 받기(캡처 또는 다운로드)  →  포토샵에 배경으로 깔기
   →  경계·라벨·범례 레이어 얹기  →  [.psd 저장]  →  JPG 로 내보내 hwp 에 삽입
```

- 베이스 레이어에 **EGIS 웹 UI**(레이어 창·줌 슬라이더)가 찍혀 있다 → 화면 캡처라는 증거
- `위성사진.psd` 는 **레이어 131개** — 카카오맵 화면 **4장(각 1,910×870)을 이어붙였다**
- **PSD 는 중간 작업 파일, 보고서에 들어가는 것은 JPG** (`생태자연도.psd` 40.7MB ↔ `.jpg` 1.3MB)

> **그래서 우리 산출물도 JPG 다.** PSD 로 뱉을 필요가 없다. 대신 **spec(JSON)을 함께 남긴다** —
> 라벨 위치를 바꾸려면 숫자만 고쳐 다시 그리면 되고 포토샵이 필요 없다.
>
> (*PSD 는 포토샵 파일 확장자다. JPG 와 달리 레이어가 따로 살아 있어 배경 지도만 꺼낼 수 있다.
> 이 성질 덕에 기존 사업의 깨끗한 베이스를 되찾을 수 있었다 — `engine/psd_base.py`*)

## 2. 어떻게 자동화했나

### 2-1. 파이프라인

```
사업 주소
   │  engine/map_fetch.py --address
   ├─ 지오코딩 (VWorld)           → EPSG:3857 좌표
   ├─ 축척 자동 선택 --fit <반경>  → 가장 먼 정온시설이 들어오는 가장 상세한 축척
   └─ 타일 취득·합성              → 베이스 지도 PNG + 메타(px_per_m · center_px)
                                        │
   engine/figure_overlay.py  ←── spec(JSON) + 메타
   └─ 오버레이·장식 그리기        → 완성 삽도 JPG
```

**메타의 `px_per_m` 과 `center_px` 가 오버레이의 입력과 그대로 물린다.** 축척을 사람이 재지
않아도 되는 이유이고, 이 연결이 파이프라인의 핵심이다.

### 2-2. 그릴 수 있는 요소와 자동화 등급

| 요소 | 자동화 | 필요한 입력 |
|---|:--:|---|
| 표적 마커 `target` · 라벨 박스 `label` | **완전** | 사업지 좌표 1개 |
| **정온시설 분포 `polar`** ★ | **완전** | **보고서의 정온시설 표 그대로** |
| 지명 `place` | **완전** | 좌표 + 이름 |
| 범례 `legend` · 축척 `scalebar` · 방위표 `north` | **완전** | 없음 (기본 배치·라벨 자동) |
| **수계흐름모식도 `watercourse`** | **완전** | 본문 서술의 하천명·거리 |
| 사업지 경계선 `boundary` | 조건부 완전 | 경계 좌표열 — 설계도서에 있다 |
| 하천 흐름 화살표 `flow` | 반자동 | 경로 점 몇 개 → 방향·간격은 자동 |
| 구역 채색 `zone` | 반자동 | 구역 경계 데이터가 따로 필요 |

### 2-3. `polar` — 표를 그림으로 옮긴다 ★

지역개황 「정온 및 개발시설 현황」 표(2.9.1)가 `라벨 | 방향 | 이격거리(m)` 형태다.
**사업지 중심과 축척만 주면 표에서 바로 지점 분포도가 나온다** — 지점마다 좌표를 찍을 필요가 없다.

```json
{"type": "polar", "origin": [375.7, 478.6], "px_per_m": 0.490196,
 "items": [{"label": "민가1", "dir": "북서", "dist_m": 212},
           {"label": "축사3", "dir": "동",   "dist_m": 156}]}
```

- **라벨은 겹치면 자리를 옮긴다** — 마커는 데이터라 그대로 두고 라벨만 8방향 후보를 돌며
  빈자리를 찾는다. 같은 방향에 6개를 30m 간격으로 몰아넣는 극단 사례로도 확인했다
- ⚠️ **16방위라 실제 방위각과 최대 ±11° 차가 난다.** 분포를 보이는 용도이고, 정확한 위치가
  필요하면 좌표를 받아야 한다
- `인접` 같은 **비수치 이격거리(평창)는 건너뛴다** — 없는 위치를 지어내지 않는다

### 2-4. 축척과 배치는 알아서 정해진다

**축척 자동 선택** — `--fit <반경 m>` 에 가장 먼 정온시설 거리를 넣으면, 그게 화면에 들어오는
가장 상세한 축척을 고른다 (라벨이 잘리지 않게 여유 25%).

```
괴산 반경 600m → L15 선택 (8.16 → 2.04 m/px, 4배 확대)
   L13 에서 한 덩어리로 뭉치던 9개 지점이 제대로 퍼졌다
```

**기본 배치** — 범례·축척·방위표는 `at` 을 안 적으면 **골든셋 정답과 같은 자리**에 놓인다.
정답 위치를 비율로 환산해 기본값으로 넣었다 (700×450 과 768×768 양쪽에서 확인).

| 요소 | 기본 위치 | 근거 |
|---|---|---|
| 세로 범례 | 오른쪽 위 `(0.708, 0.024)` | 정답 실측 (508, 11) |
| 가로 등급 띠 | 왼쪽 아래 `(0.007, 0.924)` | 정답 실측 (5, 416) |
| 축척 막대 | 등급 띠 오른쪽 옆 `(0.530, 0.930)` | 아래쪽이 [등급 띠][축척] · 그 위 [방위표] |
| 방위표 | 축척 위 `(0.927, 0.800)` | 〃 |

**축척 라벨도 계산된다** — `px_per_m` 을 주면 막대 길이에 해당하는 거리를
`10·20·25·50·100·200·250·500m·1·2·2.5·5·10km` 중 읽기 좋은 눈금으로 내리고 막대를 그에 맞춘다.
형식은 정답을 따라 **`200m ─ 0 ─ 200m`** (가운데가 0, 양쪽에 거리).

### 2-5. 스타일은 정하지 않고 뽑았다

색·굵기를 임의로 고르지 않고 **골든셋 삽도의 픽셀을 실측**했다.

| 요소 | 값 | 출처 |
|---|---|---|
| 라벨 박스 | 배경 `#636363` · 글자 `#FFF200` · 테두리 `#C81E1E` | 유역도 `사업계획지구` 라벨 |
| 표적 마커 | `#CE141E` 동심원 3겹 | 유역도 |
| 구역 채색 | `#00FFE6` (알파 150) | 유역도 상수원보호구역 |
| 흐름 화살표 | `#6CBEED` | 유역도 하천 |
| **경계선** | `#FFF200` / `#ED1C24` / `#0100FF` | **삽도 종류마다 다르다** — 생태자연도(노랑)·식생보전등급도(빨강)·국토환경성평가지도(파랑) |
| 모식도 박스 | 사업지 `#1CE2FF` · 하천 `#3F6AF7` | 수계흐름모식도 |
| 글씨 | **볼드** | 정답 라벨이 굵은 글씨 |

요소 크기는 이미지 폭에 맞춰 자동 조정된다 — 삽도 폭이 700~4,800px 로 제각각이다.

## 3. 베이스 지도는 어디서 받나 — 출처 4곳

**한 곳에서 다 받을 수 없다.** 삽도 종류마다 출처가 다르다.

| 출처 | 이 지도가 필요한 삽도 | 인증 | 상태 |
|---|---|---|:--:|
| **국토지리정보원** 지형도 | 지역개황도 · 수계도 | `~/.ngii.env` | ✅ 취득 성공 |
| **국립생태원 EcoBank** | 생태·자연도 | 공공데이터포털 키 | 🔶 경로 확인, 키 필요 |
| **ECVAM** 국토환경성평가지도 | (지역개황 밖 파트) | `~/.ecvam.env` | ✅ 취득 성공 |
| **환경부 EGIS** 환경주제도 | 각종 지정구역 | **불필요** | ✅ 취득 성공 |
| ⚠️ **카카오맵** 위성 | 위성사진 | — | ⛔ **민간 — 약관 확인 필요** |
| (없음) | 식생보전등급도 · 수계흐름모식도 | — | 자체 제작 |

### 3-1. 국토지리정보원 지형도 — WMTS ✅

```
https://map.ngii.go.kr/openapi/Gettile.do?apikey=[키]&layer=korean_map&style=korean
   &tilematrixset=EPSG:5179&Service=WMTS&Request=GetTile&Version=1.0.0
   &Format=image/png&TileMatrix=L13&TileCol=580&TileRow=1022
```

처음에 "웹 다운로드라 스크립트로 못 받는다"고 적었는데 **틀렸다.** 국토정보맵이 자기도 WMTS 로
타일을 받고 있었다.

**함정 셋** — 전부 실측으로 알아냈다.

| 함정 | 증상 | 해결 |
|---|---|---|
| 좌표계가 **EPSG:5179**(UTM-K) | Web Mercator 로 계산하면 엉뚱한 타일 | `pyproj` 변환 |
| **Referer 필수** | 15바이트 `Access_Denied` | `Referer: https://QGIS` (등록한 서비스URL) |
| **User-Agent 필수** | HTTP 400 — curl 은 되는데 파이썬은 실패 | `User-Agent: Mozilla/5.0` |

타일 격자는 국토정보맵의 OpenLayers 객체에서 직접 읽었다 (GetCapabilities 는 빈 응답):

```
origin (-200000, 4000000) · 256px
L05~L18 = 2088.96 · 1044.48 · 522.24 · 261.12 · 130.56 · 65.28 · 32.64
          16.32 · 8.16 · 4.08 · 2.04 · 1.02 · 0.51 · 0.255  (m/px)
```

이 키로 **영상지도·위성지도·백지도**도 함께 쓴다 — 카카오맵 위성사진의 공공 대체재다.

### 3-2. 생태·자연도 — EGIS 에서 EcoBank 로 이관됐다 🔶

EGIS WMS 레이어 120종을 뒤져도 생태자연도가 없어 한참 헤맸는데, EGIS 화면에 안내가 있었다:

> "생태·자연도 서비스가 하나로 통합되어 **EcoBank(에코뱅크)** 에서 서비스 됩니다."

골든셋이 이를 뒷받침한다 — 2024~2025 문서 7건은 본문에 `환경부 환경지리정보(egis.me.go.kr)의
자연환경현황도` 라고 쓰지만, **2026년 작성인 충주는 출처가 `국립생태원 Ecobank
(www.nie-ecobank.kr), 동량(377164)`** 이다. 이관을 반영한 최신 표기다.

**취득 경로는 공공데이터포털에 있다** — [국립생태원_생태자연도 서비스](https://www.data.go.kr/data/15057288/openapi.do)

```
https://apis.data.go.kr/B553084/ecoapi/EcologyzmpService/wms/getEcologyzmpWMS
   ?ServiceKey=[키]&srs=EPSG:5186&bbox=…&width=…&height=…
```

- **WMS 로 지도 이미지를 준다** (PNG·JPEG·GIF)
- **활용신청 자동승인**, 개발계정 일 10,000건
- ⚠️ 좌표계가 또 다르다 — **EPSG:5186**(중부원점). NGII 의 5179 와도 다르다

### 3-3. ECVAM 국토환경성평가지도 — TMS ✅

WMS(`apicall.do`)는 0바이트로 막히고 **TMS 로 성공**했다.

```
https://webgis.neins.go.kr/tms/ECVAM_nem_ecvam/[키]/{z}/{x}/{y}
```

- 레이어에 **`ECVAM_` 접두어**가 붙는다 (`nem_ecvam` 만 쓰면 404)
- **XYZ 방식**이다 — TMS 규약대로 y 를 뒤집으면 빈 타일이 온다
- WMS 가 막힌 이유: 그쪽은 웹페이지 임베드 전제라 **등록한 사용 URL 과 호출 출처가 일치**해야
  한다. 우리는 `QGIS` 로 등록했고, 그 등록값에 맞는 경로가 TMS 였다

### 3-4. 환경부 EGIS — 인증키 없이 된다 ✅

```
https://api.mcee.go.kr/geoserver/me/wms
```

GetCapabilities 로 **레이어 120종**(물환경 73·기후대기 56·자연환경 37) 확인, GetMap 성공.
인증키 파라미터가 아예 없다. ※ `http://` 는 302 → `https://` 로 직접 요청할 것.

### 3-5. 지오코딩 — VWorld ✅

```
https://api.vworld.kr/req/search?service=search&version=2.0&request=search
   &apiKey=[키]&domain=http://localhost&crs=EPSG:3857&format=json
   &type=address&category=parcel&query=[지번]
```

```
"충청북도 괴산군 청안면 금신리 155-1" → EPSG:3857 (14208655.633450558, 4406482.021382007)
```

ECVAM 사이트도 내부적으로 이 API 를 부른다 — 그 화면에서 읽던 좌표와 소수점까지 같다.

- `category` 는 끝 글자로 자동 판별 — `…로`·`…길` 이면 `road`, 아니면 `parcel`
- `crs=EPSG:3857` 로 요청하면 우리가 쓰는 좌표계 그대로 온다
- 키 신청 때 등록한 **서비스URL 을 `domain=` 에 그대로** 보내야 한다

> **국토정보플랫폼 검색API 는 끝내 0건이었다** — HTTP 200 에 `responseCode 1002`.
> 주소 형식 4가지 · `target`(geo/poi/des) · `refrnUrl` 을 다 시험했으나 동일. 원인 미상.

### 3-6. 인증 정리

| 파일 | 키 | 발급 |
|---|---|---|
| `~/.vworld.env` | VWorld | 도메인 등록(`http://localhost`) |
| `~/.ngii.env` | 국토지리정보원 | **회원가입 + 관리자 승인** 대기 |
| `~/.ecvam.env` | ECVAM | 이메일 인증, 사용URL `QGIS` |
| (없음) | EGIS | 불필요 |
| (미발급) | 공공데이터포털 | 생태자연도용 — **자동승인** |

코드는 파일만 읽고 **키를 로그에 남기지 않는다** (`catalog/synology_filestation.py` 와 같은 방식).

### 4-1. 국토환경성평가지도 삽도

![우리 도구 vs 정답](img/20260819_삽도_우리도구_vs_정답.jpg)

같은 배경 지도 위에 같은 구성요소가 올라간다. **남은 차이는 수치로 이렇다.**

| 항목 | 우리 | 정답 | 원인 |
|---|--:|--:|---|
| 경계선 픽셀 | 1,211 | 2,297 | 선이 조금 얇다 + 경계 좌표를 정답에서 역추출해 꼭짓점 18개로 단순화한 탓 |
| 범례 박스 | 191×88 | 184×73 | 세로로 15px 크다 |
| 등급 띠 | 381×38 | 354×28 | 글자가 조금 크다 |

전부 **숫자 조정으로 좁힐 수 있는 차이**다. 실전에서는 경계 좌표를 설계도서에서 받으므로
첫 줄의 큰 차이는 저절로 사라진다. 지금도 "같은 종류의 그림"으로 보이는 수준이다.

### 4-2. 수계흐름모식도

![수계흐름모식도 비교](img/20260819_수계흐름모식도_비교.jpg)

**입력이 본문 서술에 이미 있는 값 그대로다** —
*"인접한 구거를 따라 약 **1.93km** 유하하여 **섬강(국가)** 에 합류되며, 이후 약 **32.61km** 를
유하하여 **한강(국가)** 으로 유입된다. 총 유하거리는 약 **34.54km**"*

```json
{"canvas": [1600, 500],
 "elements": [{"type": "watercourse",
   "nodes": ["사업계획지구", "미 호 강 (국 가)", "금 강 (국 가)"],
   "links": ["15.96km", "21.56km"],
   "total": "총 유하거리 54.08km"}]}
```

`base` 없이 `canvas` 만 주면 빈 캔버스에 그린다 — 지도가 필요 없는 삽도를 위한 통로다.
괴산·원주 두 사업 데이터로 확인했다.

## 부록 B. 옛 사업의 PSD — 개발·검증 자산

NAS 삽도 PSD **34,385개** (위성사진 923 · 위치도 646 · 생태자연도 604 · 수계도 589 ·
지역개황도 253 · 정온시설 248 …). **스타일 학습과 재현 검증에 쓴다. 신규 사업의 실전 경로가 아니다.**

- HWP BinData 는 zlib raw deflate → `zlib.decompress(data, -15)` 로 풀어야 JPEG 가 나온다
- PSD 레이어를 파이썬으로 되살리면 **포토샵 레이어 효과(stroke)가 재현되지 않는다** —
  경계선이 흐리고 얇게 나온다. **우리 파이프라인은 PSD 를 거치지 않으므로 무관하다**
- 실물 확인: `raw_data/nas/figures/괴산_금신리/` (PSD ↔ JPG 쌍과 작업단계 이미지, `설명.md` 동봉)
