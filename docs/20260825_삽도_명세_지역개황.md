# 지역개황 삽도 명세 — 맥 ↔ 윈도우 인계

> 2026-08-25 · 대상 사업 **천안 화덕리** · 베이스 `templates/small-env/regional-overview.hwpx`
> 맥에서 그림을 만들고, 윈도우에서 넣고 눈으로 확인한다.

---

## 1. 왜 나눠서 하나

| | 할 수 있는 것 | 못 하는 것 |
|---|---|---|
| **맥** | 삽도 생성 — API 키(`~/.vworld.env` 등) · NAS 도엽 베이스 | 육안 검증 (PDF 렌더링이 한글을 탄다) |
| **윈도우** | 삽입 · PDF · 육안 확인 | 삽도 생성 — **키가 하나도 없다** |

삽입 자체(`generate.replace_images`)는 순수 ZIP 조작이라 어디서든 된다.
윈도우로 넘겨야 하는 이유는 **검증**이다 — BinData 를 갈아 끼우면 그림이
**기존 액자 크기에 맞춰 늘어난다.** 가로세로비가 어긋나면 찌그러지는데 PDF 를 봐야 안다.

## 3. 만들 것 — 6종 중 **5종**

| 삽도 | 만드는 쪽 | 도구 | 비고 |
|---|---|---|---|
| 생태·자연도 | 자동 | `engine/ecology.py` | EcoBank WFS — 골든셋 8/8 등급 일치 |
| **식생보전등급도** | ❌ **다른 파트 산출물** | — | 동식물상(7.1.1)에서 받아 **인용만** 한다 (rule §1) |
| 수계흐름모식도 | 자동 | `engine/hydro.py` | 직접 작도 — 원본에 베이스 지도가 없다 |
| 수계도 | 자동 | `engine/watercourse.py` + `map_fetch` | 지형도 위 하천망 |
| 정온시설 및 개발시설 현황 | 자동 | `engine/figure_overlay.py` + `parcels.py` | 사업지 경계는 편입토지조서 지번에서 |
| 지역개황도 | 자동 | `map_fetch`(지형도) + `admin.py` | **가로로 긴 액자** (1.66) |

식생보전등급도는 지역개황이 만들지 않는다. 그 자리는 `[삽도 필요]` 로 둔다.

## 4. 넘기는 방법

맥에서 PNG 를 만들어 이 경로에 둔다. **파일명이 곧 자리 지정**이다.

```
cases/small-env/천안_화덕리/regional-overview/figures/
  생태자연도.png
  수계흐름모식도.png
  수계도.png
  정온시설도.png
  지역개황도.png
```

⚠️ `raw_data/` 와 달리 이 폴더는 **git 에 올린다** (한 장에 수 MB 이면 재고).
용량이 크면 압축률을 올리거나 별도 전달을 쓴다.

## 5. 윈도우에서 넣기

```
python engine/insert_figures.py small-env regional-overview 천안_화덕리
python engine/to_pdf.py cases/small-env/천안_화덕리/regional-overview/output.hwpx
```

넣은 뒤 `check_figures()` 가 자동으로 센다. **가로 300px 이상인데 베이스와 같은
그림**이 남아 있으면 경고한다.

## 7. 알아 둘 것 — 이 문턱이 실제로 샜다

베이스에서 기준 사업 그림을 걷어낼 때 오래 **바이트(300KB)** 로 판정했다.
그래서 원주 **현장사진 4장**(429×287 · 220~285KB)이 통과해 천안 보고서에 실렸다.
압축률이 그림마다 달라 **바이트는 크기를 대변하지 못한다.**

```
사업 고유 그림   361 ~ 6,960 px
일반 아이콘       44 ~   157 px      (물방울 캐릭터 등)
```

사이가 200px 넘게 비어 **가로 300px** 로 바꿨다. 걷어낸 장수가 20 → 24 로 늘었고
베이스가 1.3MB → **331KB** 가 됐다.
