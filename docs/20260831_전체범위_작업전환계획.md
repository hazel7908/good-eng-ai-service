## 3. 현재 위치 정량화

완료 3파트(지역개황 32p·대기질 22p·소음진동 16p) = 소환 본문의 **~24%**(70/296p).
소환이 환경 카테고리 건수의 대부분이므로 카테고리 관점 체감 ~1/5,
재해까지 넣으면 **~1/10 — 미팅에서의 감각과 일치**한다.

단, 속도는 가속 중: 소음진동(인프라 구축 포함) 수 주 → 대기질 ~1주 → 지역개황
(통계 15종 + 삽도 + 베이스 + 측정) ~2주. **파트 한계비용이 급락했다.**
통계 소싱·삽도·hwpx 엔진·채점기가 재사용 자산이 됐기 때문.

## 4. 구조적 발견 — 왜 수평 확장이 싸게 먹히는가

1. **지역개황이 만능 부품이다.** 소환 2장 = 본환 4장 = 전략 준비서 4장 (절 구성 동일)
   이고, 재해 3장 기초현황도 소싱 구조가 같다. 이미 만든 통계 19종 파이프라인·판 지문·
   삽도 6종이 **전 유형에 이전**된다.
2. **파트 반복 구조.** 본환은 소환 파트들의 확장판이라, 소환 파트를 뚫으면 본환은
   "이식 + 고유 장 추가"다. 문서 관행(`(본안) NNNN` 파일 분할)도 동일.
3. **비용의 비대칭.** 천안 44.2→94.8%에서 배웠듯 마지막 30%p가 비용 대부분이다.
   러프(B수준, ~60%)는 싸다. 청양이 보여준 구조 이질성(빈칸 치환 도달 불가)은
   러프 단계에서는 문제가 안 된다 — 그 자리를 `[확인 필요]`로 두면 되기 때문.
4. **재해 4·5장은 재현하지 않는다.** 공학 계산은 AERMOD와 같은 부류로 취급:
   회사의 기존 계산 결과(엑셀 추정)를 **인풋으로 받아** 표·서술로 전개한다(할 일 3과
   동일 패턴). 계산 자체의 자동화는 10월 밖.

## 5. 전환 전략 — 수평 러프 + 사람 보완 루프

### 5-1. 완성도 사다리 (파트마다 A/B/C 라벨을 명시한다)

| 수준 | 정의 | 예 |
|:--:|---|---|
| **A** | 값·서술·조건 분기까지 자동. 남는 것은 X/판단 항목뿐 | 소음진동·대기질 |
| **B** | 구조 + 통계·기준표·계산은 자동, 사업 고유값·서술 방향은 `[확인 필요]` | 지역개황(현재), 러프 목표선 |
| **C** | 베이스 문서(빈칸) + 토큰 명세 + 필요자료 리스트 + 작성 가이드만 | 동식물상·경관·재해 4·5장 |

**10월 목표 = 환경·재해 전 유형 전 파트 최소 C, 주력 파트 B, 기존 3파트 A 유지.**

### 5-2. 품질 게이트 재정의

파트당 OK%가 아니라 **"실무자가 안심하고 이어받을 수 있는 상태"**가 게이트다:

- **WRONG 0 원칙 유지** — 모르는 값은 만들지 않고 빨간 `[확인 필요]` (기존 원칙 그대로)
- 러프 단계 공통 스모크 4종만: ① 빈칸 잔여 0 ② leak_check(기준 사업 유출 0)
  ③ `[확인 필요]` 개수·목록 리포트 ④ PDF 육안 1회
- 정답 대조 정밀 채점(score_regional류)은 **보완 단계로 미룬다** — 파트마다 채점기를
  먼저 만들면 그것만으로 몇 주가 나간다

### 5-3. 사람 보완 루프 — 5원칙 (이번 전환의 본체)

1. **모든 값에 출처 태그** — O/계산/삽도△/X/판단 분류를 전 파트 공통 vars 규약으로 (이미 있음)
2. **자동이 아닌 자리는 눈에 보이게** — 빨간 `[확인 필요]` (할 일 1, Windows 소작업) +
   `fill-report` 채움 내역서가 실무자의 작업 목록이 된다
3. **단락 방향 제안** — 자동 확정이 안 되는 단락은 조건·후보 방향을 제시 (미팅 요청 1,
   절 삽입 보류건과 통합. 러프 단계에서는 "이 단락은 무엇을 쓰는 자리" 가이드 한 줄이라도)
4. **수정본 회수 → diff → rule 후보** — 중요 사용자 2개월이 학습 기간이다.
   실무자 최종본을 NAS 규약 위치에 저장하게 하고(서비스 로그 수집 설계와 연결),
   생성본과 diff → 수정 패턴 → `(n/N)` 규율로 rule 승격. **이 루프가 돌기 시작하면
   보완 우선순위를 우리가 아니라 실무자의 수정 데이터가 정해준다**
5. **n<3 은 기본값 + `[실무자 확인]`** — 기존 규율을 러프 단계 전체에 확대 적용.
   러프 단계 rule은 기준 사업 1건 복제 + 전부 확인 표시로 시작해도 된다.
   규칙으로 굳히는 것은 보완 단계에서만

### 5-4. 작업 리듬

- **파트당 타임박스 2~4일.** 안 끝나면 C로 남기고 다음 파트로 — 도장깨기 금지의 실행 형태
- **Mac(분석·명세·vars·rule) / Windows(베이스 뚫기·생성·PDF) 주간 분리** —

| 깊이 배분 | **건수 가중** — 전 유형 최소 C, 보완은 소환 A/B > 소재 B > 본환·전략 이식+C 순 |
| 삽도 | **동결 + 사람 마무리** — 신규 유형은 베이스+가이드만. 단 §9-2 PSD 산출 요건 신설 |
| 보완 루프 학습 신호 | **둘 다** — 대화 로그(무엇이 불편한가) + 실무자 최종본 diff(무엇이 틀렸나) |
| W1 착수 | **수질(0723) + 기상(0721)** — 측정 동형·소싱형이라 기존 인프라 최대 재사용 |

범위 확인: **환경 3유형 + 재해 3유형 = 6유형 전부**가 10월 목표. 도시·인허가만 제외
(범위 파악용 레퍼런스 요청은 진행). **전략 재해 = 재해영향성검토** (08-31 확정).

### 9-2. 삽도 PSD 산출 요건 (클라이언트 신규 요청)

> "어차피 사람이 고친다는 가정이니, **고치기 쉽게 각 삽도의 PSD 파일을 떨어뜨려 달라**."

- 산출 형태: 삽도별 **레이어드 PSD** — 베이스 지도 층 + 요소별 오버레이 층(사업지 경계·라벨·화살표·채색 등)을 분리해 실무자가 포토샵에서 층 단위로 수정
- **기술 검증 완료 (08-31)**: `pytoshop`으로 쓰기 + `psd-tools`로 재판독 — 한글 레이어명·그룹 중첩 정상
  - ⚠️ RLE 압축은 pytoshop cython 모듈이 Python 3.13에서 안 빌드됨 → **무압축(raw)만 가능.** 오버레이 층을 콘텐츠 bbox로 크롭해 용량 관리. 도엽 원본 PSD 관행(수십 MB~GB)상 허용 범위
  - ⚠️ 글자는 **래스터 레이어** (포토샵 텍스트 객체 아님) → §7-7 확인
- 산출 위치: NAS (이미지 커밋 금지 규칙 유지). `figure_overlay.py`가 이미 요소별로 그리므로 층 분리 리팩터는 소규모 — W2~3 사이 타임박스 1일
- ~~파트 확장에 삽도 시간 투입~~ → 이 PSD 산출기 1건으로 삽도 신규 개발 종료

#### ✅ 구현 완료 (2026-08-31) — `engine/figure_psd.py`

`build_figures_regional.py --psd` 로 삽도별 PSD 를 함께 낸다. 요소 분기를
`_draw_element()` 로 뽑아 **평면 렌더와 층 렌더가 한 벌을 공유**한다.
실전 spec 6건 통과 · 육안 확인(층 끄기 포함) 완료.

**실측으로 드러난 함정 4건** — 전부 "통과했는데 틀린" 부류다:

| 증상 | 실체 | 왜 안 잡혔나 |
|---|---|---|
| 반경 원 라벨이 흐려짐 (최대 **18** 차이, 골든 3건) | 투명판에 그린 안티에일리어싱 글자가 **프리멀티플라이**로 남는다 | 데모는 라벨·범례가 불투명 상자를 먼저 깔아 안 걸렸다 |
| 캔버스가 1600×1200 → **1200×1600** | pytoshop `size` 는 (폭, 높이) | 층 목록·좌표는 멀쩡해 보인다 |
| Finder 썸네일이 **검정** | pytoshop 이 병합 미리보기를 0 으로 쓴다 | 포토샵은 층에서 다시 합성해 정상으로 보인다 |
| 층 이름 끝 **널 문자** | pytoshop 이 `길이=글자수+1`+`\0` 로 씀 (비표준) | NAS 실제 PSD 와 대조해서야 드러났다 |

알파 복원은 **검정·흰색 두 판** 기법이다 (`a = 1 − (Rw − Rb)/255`, `C = Rb/a`) —
그리기 내부 구현과 무관하게 정확하고, 덤으로 **밑그림을 읽는 요소 탐지기**가 됐다
(두 판에서 채널별 알파가 어긋나면 경고).

검증 둘은 **근거가 다르다**: ①내 층 합성 vs 평면 ②psd-tools 재판독(`force=True`) vs 평면.
②에서 `force` 를 빼면 우리가 쓴 미리보기를 되읽어 **자기가 쓴 것을 자기가 읽고 통과**한다.
음성 시험으로 둘 다 실제로 울리는 것을 확인했다.
