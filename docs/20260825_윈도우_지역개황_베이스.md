```powershell
python catalog\synology_filestation.py download "/backupenv/0. 평가서/환경/환25-09 원주시 호저면 무장리 태양광발전시설 조성사업(주식회사 썬파워)/lsy 원주시 무장리 태양광/2. 보고서/(본안) 0200 지역개황(완) 9-40.hwp" --dest raw_data\nas\regional-overview\원주_무장리\ --yes
```

경로가 안 맞으면 (NAS 재편이 진행 중이다) 이렇게 찾는다:

```powershell
python catalog\synology_filestation.py tree "/backupenv/0. 평가서/환경" --depth 2 | findstr "무장리"
```

> **vars 는 커밋돼 있다** — 통계 값이 이미 그 안에 들어 있어 값 저장소도 NAS 도 필요 없다.
> 사업 4건(원주·천안·괴산·청양) 전부 준비돼 있다.

## 1. 원본을 hwpx 로 저장 — 수작업

한글에서 열어 **다른 이름으로 저장**한다. 경로·이름을 정확히 맞출 것.

```
raw_data\nas\regional-overview\원주_무장리\(본안) 0200 지역개황(완) 9-40.hwp
  → raw_data\nas\regional-overview\원주_무장리\0200_지역개황.hwpx
```

## 2. 베이스 문서 만들기

```powershell
python engine\build_template.py regional-overview
```

치환 18건이 돌고 토큰이 대조된다. **Mac 에서 미리 검산했다** —
추출본 기준 찾기 문자열 15/16 존재(사업명 1건은 머리글이라 추출본에 없다),
생성 토큰 27종, 잔여 `원주시` 1회.

### ⚠️ 그 잔여 1회는 버그가 아니다

법령표 안의 예시다 (대기환경보전법 별표10의2 저황유 공급지역 `춘천시, 원주시, 강릉시`).
사업과 무관하므로 **바꾸면 안 된다.** `REGIONAL_OVERVIEW_REPLACE` 가 임시 토큰으로
감쌌다가 되돌린다 — 치환 목록의 **순서가 의미를 갖는다.** 순서를 바꾸지 말 것.

### 토큰이 MISSING 으로 뜨면

찾기 문자열이 원본과 안 맞는 것이다. **가운뎃점 3종**(`·` U+00B7 · `ㆍ` U+318D ·
`‧` U+2027)과 스마트따옴표 때문이다. **손으로 고치지 말고** 원본에서 복사해
`build_template.py` 의 해당 줄을 바꾼다.

## 3. 원주 원본의 오류 3건을 교정 — 수작업

베이스에 그대로 전파되므로 여기서 고친다 (`slots.md` §베이스로 뜨기 전에 교정할…).

| 자리 | 원본 | 교정 |
|---|---|---|
| 40줄 | `임야의 구성비가 51.49%(67.09㎢)` | 값이 뒤바뀌었다 → `67.09%(51.49㎢)` |
| 41줄 캡션 | `원주시 및 **무장리**의 지목별…` | 데이터는 호저면 → `원주시 및 호저면의…` |
| **2.7.1 표** | **8개 값이 전부 ÷10** | 아래 표대로 |

```
원주        15,600 / 12,460.45   →   156,000 / 124,604.5
흥업         1,300 /    567.94   →    13,000 /   5,679.4
원주기업도시  1,260 /    707.11   →    12,600 /   7,071.1
문막           700 /    467.98   →     7,000 /   4,679.8
```

> 괴산(8,000↔8,000)·천안(220,000↔220,000)은 원자료와 1:1 이다 — **원주 문서만의
> 오류**다. 인구 36만 도시의 하수처리량이 18,860㎥/일일 수 없다.

## 4. §B 표 편집기 작성 — 여기가 본체다

`engine/generate.py` 의 `tables_regional_overview()` 가 지금 `NotImplementedError` 다.
**표 17개**를 채워야 한다. vars 의 `통계` 에 **값은 이미 준비돼 있다.**

```powershell

```

| 표 | vars 키 | 행 수 |
|---|---|---|
| 2.6-1 취수장 · 2.6-2 정수장 | `2.6.1 취수장` · `2.6.2 정수장` | 가변 |
| 2.7-1~5 환경기초시설 | `2.7.1`~`2.7.5` | 가변 (0행 = 지정 없음) |
| 2.3-4 상수원보호구역 · 수변구역 | `2.3.2 …` | 가변·유무 분기 |
| 2.3-8 야생생물 · 2.3-9 산림유전자원 · 자연공원 | `2.3.3 …` | 가변 |
| 2.5-1 도로 · 2.5-2 배출시설 · 2.5-3 산업단지 · 2.5-4 자동차 | `2.5.…` | 고정/가변 |
| 2.2-1 지목 · 2.2-3 용도지역 · 2.6-3 문화재 | `2.2.…` `2.6.3` | 고정 |
| 2.8-1 하천일람 | `2.8.3 하천일람` | 가변 |

**참고할 것**: `tables_noise_vib()` · `tables_air_quality()` 가 같은 일을 한다
(`find_in_table` 로 앵커를 찾고 `set_cell` 로 채우고 행을 늘린다).
표 행 확장은 소음진동 7·8·10행에서 검증됐다 — 문제없었다.

### ⚠️ 0행이 정상인 표가 있다

원주는 소각시설·생태경관보전지역·습지·백두대간이 **전부 "지정 없음"** 이고 그게 정답이다.
0행이면 **표를 빼고 문장만** 쓴다 (rule §4-3). 표를 빈 채로 남기지 말 것.

## 6. 검증

```powershell
python engine\generate.py small-env regional-overview 원주_무장리
python engine\to_pdf.py cases\small-env\원주_무장리\regional-overview\output.hwpx
```

`/validate-report` 6단계로 정답과 대조한다.

### ⚠️ 원주로 점수를 재지 말 것

원주는 **베이스의 출처 사업**이다. 자기 자신을 재생성하는 것이라 점수가 부풀려진다.
측정은 **천안 화덕리**로 한다 — 통계연보 원자료를 가진 유일한 사업이라 절이 가장 많이
채워진다(17/24). 소음진동에서 괴산으로 재다가 같은 함정을 밟은 적이 있다.

### ⚠️ 정답과 다른 것이 전부 우리 오류는 아니다

오늘 원자료 대조에서 **정답지 쪽 문제를 여럿 찾았다.**

| 사업 | 무엇 |
|---|---|
| 천안 | 하수처리·취수장이 **2021판** (출처는 `2023`), 취수장은 **일최대취수량 열** |
| 괴산 후평 | 출처만 2024 로 갈고 **값은 금신리 것을 복사** |
| 원주 | 자연공원 175.668 ↔ 2024·2025판 모두 176.567 |
| 표 머리글 | 상수원보호구역 `천㎡` ↔ 실제 ㎢ · 산업단지 `천㎡` ↔ 실제 ㎡ |

**연도 행 차이가 특히 많이 나올 것이다** — 우리는 "최신 행" 이 기본값이고,
정답지는 절마다 다른 행을 썼다. 이것이 확인요청 **F-1** 그 자체다.
검증표에 `정답지 문제` 칸을 따로 두고 세지 말 것.
