# 검토서 B — 옥계리 인풋 수확, **NAS 가 아니라 이미 가진 것**부터 (2026-09-09)

대기열의 "검토서 B → 횡성 옥계리 인풋 수확 (Windows 여유 슬롯)"을 착수하며 조사한 결과다.

## 1. 🚨 횡성_옥계리 검토서 = **본환 횡성_벨라스톤CC 와 같은 사업**

골든 1장 첫 문단 실측:

> 계획대상지는 “강원도 횡성군 서원면 **옥계9길 124번지** 일원”에 위치하고 있으며 …
> **9홀 증설**로 급증하는 골프장 수요에 대처하여 …

`벨라스톤` 2회 · `골프` 14회 · `증설` 3회. 본환 기준 사업(`env-impact/횡성_벨라스톤CC`
— 벨라스톤C.C 증설, 서원면 옥계리, 1,239,132.2㎡, 9홀 증설)과 **동일 사업**이다.

→ **NAS 수확이 필요한 일이 아니다.** 그 사업의 자료는 이미 저장소에 있다.

## 2. 그래서 무엇이 이미 있고 무엇이 없나

검토서 vars 는 `slots` 평면이 아니라 **중첩 구조**다(기준: 원주_태장동).

| 파트 | 필요한 묶음 | 벨라스톤 자료로 되나 |
|---|---|---|
| project-overview | 계획·서술·경위·위치도_라벨·토지이용 | **계획명/위치/면적/사업기간/시행자 ✅**(본환 vars) · 토지이용 지목별·소유별 ✅(본환 land-use 조서) · **경위·위치도 라벨 ❌** |
| target-area | 사업·서술·사유 | 사업 ✅ · 서술·사유 ❌(검토 판단) |
| baseline-survey | 관측소·기상·수계·지질·재해·위험지구·방재시설·관련계획·지구지정 | 관측소·기상 ✅(본환 climate) · 나머지는 **소재평 3장과 같은 공공데이터 소싱** |
| risk-analysis | 총괄·방재성능·방재시설 관리상태 | ❌ — 4장은 유형별 위험요인 **판단** |
| appendix | 총괄자·대행비용·설계업체 | 회사 상시 — 원주 태장동 것 승계 가능 |

## 3. 판단이 필요한 지점 — 맥·실무자 몫

⚠️ **본환 보고서를 검토서의 인풋으로 써도 되나.** `raw_data/nas/env-impact/횡성_벨라스톤CC/`
는 본환 골든의 원천이다. 검토서는 **다른 산출물**이라 `정답지 참조 금지`(같은 산출물의 정답)에
걸리지는 않지만, 실무에서 검토서는 보통 **환경영향평가보다 앞선다**(지구단위계획 단계).
시간 순서를 거스르는 인풋을 쓰면 "이 자동화가 실제로 가능한가"를 스스로 속이게 된다.

→ 두 갈래 중 선택이 필요하다:
  **㉮** 본환 자료를 인풋으로 인정(같은 사업의 다른 문서 재사용은 실무 관행이기도 하다)
  **㉯** 지구단위계획 입안 자료를 NAS 에서 따로 찾는다(검토서 실제 인풋)

## 4. 크기 판정 — "여유 슬롯"이 아니다

되는 것을 다 긁어모아도 **baseline-survey 9묶음 중 7묶음**이 소재평 3장과 같은
공공데이터 소싱(재해이력·위험지구·방재시설)이고, risk-analysis 4장은 **판단 서술**이다.
착수하면 소재평 3장 소싱 재사용 설계부터 해야 한다 — 하루짜리가 아니다.

**Windows 가 지금 할 수 있는 것**: 위 표의 ✅ 칸(계획·토지이용·기상)을 벨라스톤 vars 에서
옮기는 어댑터. 나머지는 소싱 층이 서고 난 뒤다.
