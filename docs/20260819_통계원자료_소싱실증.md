# 지역개황 통계 원자료 — 소재 조사와 매핑 실증 (2026-08-19)

> 미팅 §2 의 두 요청을 실측으로 확인한 기록.

> ② *"중요 통계를 체계적으로 관리할 방법"* → **관리 단위가 무엇이어야 하는지 §5 에 제안.**

## 1. 한 줄 결론

**통계연보 엑셀 → 보고서 표 매핑은 기계적으로 성립한다** (천안 2개 절 전수 일치).
막히는 것은 매핑이 아니라 **원자료 확보** — 지자체가 배포 형식을 제각각 쓴다 (§3).
덤으로, **정답지가 절마다 다른 연도 행을 인용하고 있었다** (§4-3).

## 3. 배포 형식이 자동화 가능성을 가른다 ★

통계연보 91건의 형식:

| 형식 | 건수 | 자동화 |
|---|--:|---|
| `.zip` | 43 | **내용에 따라 갈림** — 엑셀 묶음이면 최상, 스캔 PDF 묶음이면 최악 |
| `.pdf` | 34 | **스캔이면 OCR 필요** (§3-2) |
| `.hwp` | 9 | 통계청 배포 원본(전편·부록) — 파싱 가능 |
| `.xlsx`/`.xls` | 4 | 최상 |

### 3-1. 엑셀 배포 — 천안 (좋은 쪽)

`2023년 통계연보.zip` (2.6MB) 안에 **편별 엑셀 21개**가 들어 있다.

```
01.연 혁 · 02.토지 및 기후 · 03.인 구 · 04.노 동 · 05.사업체 · 06.농림수산업 ·
07.광업·제조업 및 에너지 · 08.전기·가스·수도 · 09.유통·금융 · 10.주택·건설 ·
11.교통·관광 · 12.보건 및 사회보장 · 13.환 경 · 14.교육 및 문화 · 15.재정 ·
16.공공행정 및 사법 · 17.부 록
```

편 구성이 **통계청 표준**이라 지자체가 달라도 같다. 시트 이름도 규칙적이다
(`02.토지 및 기후` → `1-행정구역` / `2-토지지목별현황` / `3-일기일수` / `4-기상개황` / `5-강수량`).

> ⚠️ zip 내부 파일명이 **CP949** 라 `unzip` 이 실패한다. Python `zipfile` +
> `name.encode('cp437').decode('cp949')` 로 풀어야 한다.

### 3-2. 스캔 PDF — 평창 (나쁜 쪽)

`2022년 평창통계연보(제62회).pdf` (31.8MB, **323쪽**) — `pdffonts` 결과 **폰트 0개**,
전 페이지가 JPEG 이미지다. `pdftotext` 로 나오는 텍스트가 **323바이트**뿐.

**이 판본은 OCR 없이는 값을 못 꺼낸다.** 보고서 출처 표기와 판본이 완전히 일치하는(§4-1)
유일한 사업이었는데, 정작 기계 처리가 가장 어렵다.

### 4-1. 지목별 토지이용 (보고서 §2.2.1) — **완전 일치**

`02.토지 및 기후.xlsx` → 시트 `2-토지지목별현황`

| 항목 | 통계연보 (㎡) | ÷10⁶ | 보고서 (㎢) |
|---|--:|--:|--:|
| 천안시 합계 | 636,150,972.60 | 636.15 | **636.15** ✅ |
| 전 | 51,882,965.60 | 51.88 | **51.88** ✅ |
| 답 | 92,851,695.40 | 92.85 | **92.85** ✅ |
| 임야 | 309,017,902.80 | 309.02 | **309.02** ✅ |
| 대 | 39,694,527.20 | 39.69 | **39.69** ✅ |
| 과수원 | 15,683,042.30 | 15.68 | **15.68** ✅ |
| **동면** 합계 | 43,270,000 대 | 43.27 | **43.27** ✅ |
| 동면 전/답/임야/대 | | 4.57 / 6.23 / 26.18 / 0.86 | **동일** ✅ |

**변환 규칙**: `㎡ → ㎢` (÷1,000,000), 소수 **2자리 반올림**. 구성비는 rule §3-1 공식으로 재계산.

### 4-2. 자동차 등록현황 (보고서 §2.5.4) — **완전 일치**

`11.교통.관광.xlsx` → 시트 `1-자동차등록`

| 항목 | 통계연보 2022년 행 | 보고서 |
|---|--:|--:|
| 계 | 351,796 | **351,796** ✅ |
| 승용차 | 294,246 | **294,246** ✅ |

### 4-3. ⚠️ 그런데 절마다 인용한 연도가 다르다

| 절 | 통계연보에서 쓴 행 |
|---|---|
| §2.2.1 지목별 토지이용 (시 전체) | **2021년** |
| §2.2.1 지목별 (동면) | **2022년** (읍면동 블록은 최신년 기준 — 구 합계 636.16 = 2022) |
| §2.5.4 자동차 | **2022년** |

같은 통계연보 안에서 **시 전체는 2021년, 면은 2022년**을 썼다. 출처 주석은 셋 다
`2022년 기준 통계연보. 천안시. 2023` 로 동일하다.

원인은 시트 구조로 보인다 — 연도 블록이 `2018·2019·2020·2021`(12행) **빈 행** `2022`(14행) 로
끊겨 있어 **마지막 행을 놓치기 쉽다.**

> **자동화의 실질 이득이 여기 있다.** 계산이 어려워서가 아니라, **사람이 헷갈리는 자리를
> 기계가 정확히 집기 때문이다.** 단 "어느 연도 행을 쓸 것인가"는 회사 표준이 필요하다
> → `docs/실무자_확인요청.md` 에 추가할 항목.

## 5. 통계 관리 체계 — 관리 단위 제안

미팅 §2 의 "중요 통계를 체계적으로 관리할 방법"에 대한 답의 뼈대.

### 5-1. 두 종류를 분리해야 한다

| 종류 | 갱신 축 | 관리 방식 |
|---|---|---|
| **지자체 통계연보** (20개 지자체 × 연도 × 회차) | 사업 소재지마다 다름 | **지자체 × 발간회차** 로 카탈로그. 최신판 1개 + 인용된 과거판 보존 |
| **전국 통계** (상수도·하수도·폐기물·상수원보호구역·야생생물·습지·자연공원·하천일람 등 ~12종) | 연 1회 전국 공통 | **자료 종류 × 발행연도** 로 카탈로그. 전 사업이 같은 판을 쓴다 |

### 5-2. 카탈로그에 들어갈 필드 (초안)

`지자체 | 자료명 | 회차 | 기준연도 | 발간연도 | 형식(엑셀/PDF스캔/hwp) | NAS 경로 | 인용 사업`

**형식 칸이 핵심**이다 — 엑셀이면 자동 추출, 스캔 PDF 면 OCR 대상, 이 구분이 곧 작업량이다.

### 5-3. 카탈로그 v2 (할 일 4)와의 관계

`catalog/build_catalog.py` 는 지금 **보고서**를 분류한다. 통계 원자료는 다른 축이므로
**별도 인덱스**로 붙이는 게 맞다 (`catalog/data/stats_catalog.json`). NAS 재크롤 때 같이 뜬다.

## 6. 삽도 — 3층 구조 (미팅 §5)

원주 지역개황 원본에서 삽도 **30장·51.4MB** 를 추출해 확인했다 (파일 크기의 **99%가 삽도**).
HWP BinData 는 zlib raw deflate 압축이라 `zlib.decompress(data, -15)` 로 풀어야 JPEG 가 된다.

| 층 | 내용 | 자동화 |
|:--:|---|---|
| **① 베이스 지도** | 국토지리정보원 지형도 / 환경부 EGIS 자연환경현황도 / 식생도 | **캡처 필요** — 서비스별 다름. 수동 캡처가 현실적 시작점 |
| **② 오버레이** | 사업지 경계 폴리곤 · `사업계획지구` 라벨 박스 + 지시 화살표 · 구역 채색 · 지명 라벨 · **하천 흐름 화살표** | **여기가 자동화 대상** |
| **③ 장식** | 범례 · 축척 막대 · 방위표 | 템플릿 고정 |

실측한 3장의 유형:

| 삽도 | 베이스 | 오버레이 |
|---|---|---|
| **유역도(수계도)** | 지형도 1:75,000 | 표적 마커 + `사업계획지구` 라벨 · **하천 흐름 화살표 20여 개(수계별 색 구분)** · 상수원보호구역 청록 채색 + 라벨 · 하천명 원문자 |
| **생태·자연도** | EGIS 캡처 (등급 채색·범례 포함) | 사업지 **노란 경계선** + 라벨 박스 + 화살표 |
| **식생보전등급도** | GIS 도면 (등급별 폴리곤) | 사업지 **빨간 경계선** + 범례·축척·방위표 |

> **클라이언트 질문("이런 것도 가능한지")에 대한 답**:
> - 라벨 박스·표적 마커·지명 — **사업지 좌표 1개만 있으면 지금 가능**
> - 사업지 경계선(노랑/빨강) — **설계도서의 경계 좌표가 있으면 가능**. 이미 사업마다 존재한다
> - 하천 흐름 화살표 — 경로를 따라 배치해야 해 **반자동**(경로 클릭 → 자동 배치)
> - 구역 채색 폴리곤(상수원보호구역 등) — **별도 경계 데이터 필요**. 난이도 최상
> - 베이스 지도 캡처 — 서비스 이용약관 확인이 먼저다

## 7. 구현 (같은 날 완료) ✅

### 7-1. 통계 카탈로그 — `catalog/build_stats_catalog.py`

NAS 인덱스에서 통계 원자료를 뽑아 **사업이 아니라 통계 자료**를 축으로 정리한다.

```bash
python catalog/build_stats_catalog.py
# 고유 236건 (통계연보 59 · 전국 통계 177)
#   → catalog/data/stats_catalog.json · catalog/review/stats_catalog.md
```

`지자체 | 자료명 | 회차 | 연도 | **형식** | NAS 경로 | 사본` — §5-2 의 필드를 그대로 담는다.
사본이 여러 벌인 판은 한 항목으로 묶는다(당진 제61회 4벌 등).

### 7-2. 엑셀 → 표 추출기 — `engine/stats_extract.py`

`calc.py`(소음진동)·`calc_air.py`(대기질)와 같은 자리의 파트 모듈. **계산이 아니라 소싱**이다.

```bash
python engine/stats_extract.py --self-test          # 천안 골든셋 대조
python engine/stats_extract.py <통계연보> --region 동면
python engine/stats_extract.py <통계연보> --what sheets   # 절↔시트 매핑 확인
```

**자체 검증 결과 — 21항목 전부 일치** (지목별 시군 6 · 면 6 · 자동차 6 · 구성비 3).
zip 직접 읽기(CP949 파일명 처리) · 헤더 텍스트로 열 찾기 · 연도 행 선택 · ㎡→㎢ 변환 포함.

| 절 | 시트 (천안 실측) | 상태 |
|---|---|:--:|
| 2.2.1 지목별 토지이용 | `02.토지 및 기후` / `2-토지지목별현황` | ✅ 검증 |
| 2.5.4 자동차 | `11.교통.관광` / `1-자동차등록` | ✅ 검증 |
| 2.2.2 용도지역 | `10.주택.건설` / `9-용도지역` | ⬜ 매핑만 |
| 2.5.1 도로 | `10.주택.건설` / `12-도로` | ⬜ 매핑만 |
| 2.5.2 배출시설 | `13. 환 경` / `1-환경오염물질배출사업장` | ⬜ 매핑만 |
| 2.6.3 문화재 | `14-02.교육 및 문화` / `19-문화재` | ⬜ 매핑만 |

⬜ 4개는 **시트를 찾는 것까지는 되고**(`--what sheets` 로 확인) 표 구조별 파서만 남았다.
검증할 골든셋 값이 있는 절부터 붙이는 게 맞다 — 무검증 파서를 늘리지 않는다.
