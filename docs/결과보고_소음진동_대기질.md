> **대상 파트**: 소음·진동(7.2.7) · 대기질(7.2.2) — 소규모 환경영향평가
> **기간**: 2026-07-28 ~ 2026-08-05 · **상세 이력**: `git log` (커밋마다 무엇을·왜 했는지 기록)
> **이 문서의 목적**: 지금까지의 결과물과 과정을 공유하고, 다음 단계를 함께 정하기 위함

## 1. 한눈에 — 무엇이 만들어졌나

**보고서 2개 파트를, 신규 사업 인풋만 넣으면 초안이 자동으로 나오는 상태**까지 만들었습니다.

```
[신규 사업 인풋]              [지식·규칙]                [생성 엔진]
사업개요·측정자료       +    골든셋 7건에서 도출한   →   한글(HWP) 자동 조작    →   초안 HWPX
실무 계산 엑셀               파트별 규칙                 (빈칸 치환+표 계산·편집)     + [확인 필요] 표시
```

| 파트 | 상태 | 정확도 (완성 보고서와 문장·수치 단위 대조) |
|---|---|---|
| 소음·진동 (7.2.7) | 생성→검증 3개 사업 완료 | 천안 **75.3%** · 괴산 59.0% · 청양 50.0% (시작점 44.3%) |
| 대기질 (7.2.2) | 생성→검증 1개 사업 완료 | 평창 — **계산 수치 오차 0건** (배출량·예측 전 체인이 실무 엑셀과 일치) |

정확도에 안 잡히는 중요한 특징: **인풋에 없는 값은 지어내지 않고 `[확인 필요]` 로 표시**합니다.
초안에서 실무자가 채울 곳이 눈에 보입니다.

## 2. 왜 이 파트부터 했나

### 카테고리 선택 — 소규모 환경영향평가

NAS 보고서 290건을 분류한 결과(`catalog/data/nas_catalog.json`) **소규모 환경영향평가가 76건으로
가장 많았습니다.** 물량이 가장 많은 곳부터 자동화 효과가 큽니다.

### 파트 선택 — 소음·진동 → 대기질

소규모 환경영향평가 한 권은 9개 파트로 구성됩니다 (천안 완본 목차로 확정 — `docs/naming.md`):

```
7.1.1 동식물상 / 7.2.1 기상 / 7.2.2 대기질 / 7.2.3 수질 / 7.2.4 토지이용
7.2.5 지형지질 / 7.2.6 친환경적 자원순환 / 7.2.7 소음·진동 / 7.2.8 경관
```

| 순서 | 파트 | 이유 |
|:--:|---|---|
| 1 | **소음·진동** | 구조가 정형적(측정→예측 계산→저감)이고 **계산이 공식으로 재현 가능** — 자동화 검증에 최적 |
| 2 | **대기질** | 소음·진동과 **인풋·구조를 공유** (영향예측지점, 투입장비, 일 작업량). 파이프라인이 딴 파트로 이식되는지 확인하는 시험대 |

실제로 대기질은 소음·진동에서 만든 도구를 **그대로 재사용**해 훨씬 빨리 끝났습니다
(소음·진동 약 1주 ↔ 대기질 이틀).

## 3. 어떤 방식으로 했나

### 3-1. 원칙 — "정답을 베끼지 않는다"

완성 보고서(골든셋)는 **규칙을 도출하고 결과를 채점할 때만** 열고, 생성은 신규 사업 인풋만으로 합니다.
실무에서는 정답이 없기 때문입니다. 인풋에 없는 값은 `[확인 필요]` / `[모델링 필요]` 로 표시합니다.

### 3-2. 3단 구조 — 문서·데이터·규칙의 분리

| 층 | 무엇 | 위치 |
|---|---|---|
| **베이스 문서** | 완성 보고서에 빈칸(`{{토큰}}`)을 뚫은 시작 파일. 소음진동 35종·대기질 19종 | `templates/small-env/noise-vib.hwpx` · `air-quality.hwpx` (빈칸 명세: 같은 폴더 `*.slots.md`) |
| **사업 데이터** | 사업별 입력값·판단값 (JSON) | `cases/small-env/{사업}/vars/` · 인풋 원문 `cases/small-env/{사업}/input/` |
| **파트 규칙** | 골든셋에서 도출한 지식 — 변수 출처·계산 공식·분기·오류 사례 | `.claude/rules/small-env/noise-vib.md` · `air-quality.md` · 공통 `.claude/rules/common.md` |

> **사업 데이터(vars JSON) = 값의 나열이 아니라, 그 사업에 대해 확정한 사실들의 대장(臺帳)**
> — 인풋에서 추출한 값 · 기본값 + `[실무자 확인]` 표시한 판단값 · 인풋에 없어 비워 둔 값.
> 사실이 어떤 **문장·표**가 되는지는 엔진에 고정 — "측정자료가 인용" 사실 **1개**를 적으면
> 도입 문장·삽도 캡션·자료유형 등 **4곳**이 함께 바뀝니다. 사업마다 판단할 것은 대장의 사실뿐입니다.

생성 엔진(`engine/generate.py`)은 한글 프로그램을 자동 조작해 빈칸을 채우고 표를 편집합니다.
계산은 별도 모듈(`engine/calc.py` · `calc_air.py`)이 하며 **자체 검증**(골든셋 실측값 대조)을 내장합니다.
생성물 옆에는 검토자용 **채움 내역서**(`fill-report.md`)가 함께 만들어집니다 — 직접 채워야 할 값 ·
확인이 필요한 값 · 자동 채움 값을 근거와 함께 구분해, 초안의 어디를 믿고 어디를 고칠지 보여줍니다.

### 3-3. 검증 사이클 — 규칙은 다수결로만 굳힌다

```
생성 → 완성 보고서와 전 항목 대조 → 오류의 원인 분류 → 규칙·코드 수정 → 재생성
```

핵심 규율: **한두 건에서만 관측된 것은 규칙으로 쓰지 않고 `(n/7)` 근거 건수를 명기**합니다.
실제로 한 사업(괴산)에서 일반화했던 규칙 4개가 다른 사업들에서 틀린 것으로 판명돼 고쳤고,
거꾸로 표본을 7건으로 늘리자 "우세"였던 항목이 뒤집힌 사례도 두 번 있었습니다.
사업 간 비교표는 `golden/small-env/_variants.md` 에 전부 기록돼 있습니다.

### 3-4. 육안 검증 자동화

텍스트 비교로 안 잡히는 결함(표 캡션이 다음 쪽으로 분리, 셀 줄바꿈, 볼드/음영)을 잡기 위해
**PDF 변환 → 페이지 이미지 확인**을 절차화했습니다 (`engine/to_pdf.py`, 결과 `docs/layout_review.md`).
실제로 전 사업에 걸린 캡션 분리 결함을 여기서 발견해 고쳤습니다.

## 4. 결과 상세

### 4-1. 소음·진동 — 3개 사업 생성·검증

| 사업 | 정확도 | 생성물 | 검증 리포트 |
|---|:--:|---|---|
| 괴산 금신리 | 44.3%(구 PoC) → **59.0%** | `cases/small-env/괴산_금신리/noise-vib/output.hwpx` | 같은 폴더 `validation.md` |
| 천안 화덕리 | 44.2% → **75.3%** | `cases/small-env/천안_화덕리/noise-vib/output.hwpx` | 〃 |
| 청양 매곡리 | 36.0% → **50.0%** | `cases/small-env/청양_매곡리/noise-vib/output.hwpx` | 〃 |

- 자동화된 것: 빈칸 35종 · 표 계산(합성소음도·거리감쇠·저감 3단계·**가설방음판넬 열 추가**) ·
  표 행 수 조절(사업별 5~10지점) · 법령표 볼드/음영 이동 · 조건 분기(저감 절 유무·측정자료 인용 여부) ·
  삽도 교체
- **남은 오류의 대부분은 자동화 한계가 아니라 인풋 한계**입니다. 천안 잔여 19건 중 16건이
  삽도(지도 이미지)에서 거리를 읽은 오차였고, 청양처럼 **지역개황편에 좌표·거리 표**가 있으면
  10곳 중 9곳이 정확히 맞았습니다. → §6 논의사항 1

### 4-2. 대기질 — 1개 사업 생성·검증

| 사업 | 결과 | 생성물 | 검증 리포트 |

- 배출량 산정 전 체인(일 작업량 → 비산먼지 q1~q4 → 총 배출량 → 예측 → 저감 후)이
  **실무 계산 엑셀·완성 보고서와 3자 일치**했습니다.
- ★ 이 과정에서 **실무 산출물의 소재를 확인**했습니다: NAS `기타자료/3. 엑셀/` 의
  `대기질계산(사업).xlsx`(계산 원본)과 `대기질 결과값(사업).xlsx`(**AERMOD 모델링 가중치**).

## 5. 어려움 — 해소된 것과 남은 것

### 해소된 것

| 어려움 | 어떻게 풀었나 |
|---|---|
| 한글 문서 자동 편집의 함정 (빠른교정이 문자를 바꿈, 병합 셀에서 커서가 어긋남, 검색어 부분매칭 등 10여 건) | 전부 실측으로 잡아 **오류 레지스트리에 축적** — `.claude/rules/small-env/*.md` §6. 파트가 달라도 같은 함정이 나와 재사용됨 |
| 계산이 보고서와 0.1 단위로 어긋남 | 실무 방식이 "**표에 적힌 반올림 값으로 후속 계산**"임을 실무 엑셀로 확인하고 재현 |
| 문서 레이아웃 결함(캡션 쪽 분리 등)을 볼 방법이 없음 | PDF 변환 육안 검증 절차화 |
| 사업마다 문서 구조가 다름 (절이 통째로 생기고 없어짐) | 절 삭제·표 열 추가는 자동화 완료. 절 삽입은 도구만 준비(아래) |
| 여러 곳에 흩어진 인풋 (성적서·설계도서·계산 엑셀·타 파트) | NAS 검색·다운로드 자동화 (`catalog/synology_filestation.py`) + 인풋 소재 지도를 규칙에 기록 |

### 남은 것 — ①안에서 풀 수 있는 것

| 항목 | 상태 |
|---|---|
| 절 삽입 (평창 고농도 미세먼지 절, 방진망 법령표 등 소수 사업 전용 절) | 오려둔 조각과 도구는 준비. **투입 조건을 실무 확인 후** 구현 예정 |
| 대기질 예측결과 표의 행 수 조절 (병합 3행 구조) | 미구현 — 지점 수가 5와 다르면 표시 후 수동 보정 |

### 남은 것 — ②실무 확인이 필요한 것 (기술로는 못 정함)

**완성 보고서 7건이 서로 다르게 쓰고 있어 기계가 판단할 수 없는 항목**이 양 파트에 걸쳐 있습니다.
전부 질문지로 정리했습니다 → **`docs/실무자_확인요청.md`** ★

대표 예: 저감 계산의 반올림 방식(사업 간 상반 — **판정을 뒤집는 항목**), 상회 없을 때 최종표 유무(2:2),
대기질 유지목표농도 산정 근거(평창이 국가 기준보다 강함), 측정일시·지점명 표기(4가지 혼용).
