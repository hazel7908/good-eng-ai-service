# 이름 대응표 — 한글 ↔ 영문

> **왜 이 문서가 있나**: 폴더 이름이 곧 지식 스코핑 설계이기 때문이다. rule의 `paths:` 패턴에 **글자로 박히는 이름**이 흔들리면 로드가 **에러 없이 조용히 실패**한다.
> **설계 근거**: `repo_restructure_plan.md` §2 ① · §6

---

## 표기 원칙 — 경로 패턴에 글자로 박히는 것만 영문

```
cases/small-env/*/noise-vib/**
      └───┬───┘ ┬ └───┬───┘
       카테고리  │    파트
        영문     │    영문
                사업
              = * (와일드카드) → 한글
```

| 축 | 경로 패턴에서 | 표기 | 예 |
|---|---|:--:|---|
| 인프라 폴더 | 글자로 박힘 | **영문** | `templates/` `golden/` `cases/` `engine/` `catalog/` |
| **카테고리** | 글자로 박힘 | **영문** | `small-env` |
| **파트** | 글자로 박힘 | **영문** | `noise-vib` |
| **사업** | `*` 로만 쓰임 | **한글** | `괴산_금신리` |
| 내용 전부 | (경로 아님) | **한글** | rule 본문 · 문서 · 보고서 · 변수명 |

**한 줄로**: 매칭에 실제로 쓰이는 이름만 영문.

**형식**: 소문자 + 하이픈(`kebab-case`). 밑줄·대문자·공백 금지. 단 **사업만 밑줄**(`괴산_금신리`) — 시군과 리를 가르는 구분자이고 경로 매칭에 쓰이지 않는다.

## 사업

**영문화하지 않는다.** 한글 그대로 `{시군}_{리}` 를 쓴다.

```
괴산_금신리    원주_무장리    여주_광대리    청양_매곡리    천안_화덕리
```

**이유**:
- 경로 패턴에서 항상 `*` 로 처리되므로 **영문화해서 얻는 게 없다**
- 290건 이상이 계속 늘고, 로마자 표기가 사람마다 갈린다 (`goesan` / `gwesan`)
- 한글 검색이 막힌다

**한글 경로 매칭은 실측으로 확인됐다** (2026-07-28, `repo_restructure_plan.md` §1 관측 5): `golden/small-env/*/noise-vib*` 패턴이 `괴산_금신리` 를 통과했다.

시군 표기는 **카탈로그의 `위치` 필드를 따른다** (`괴산군 청안면 금신리` → `괴산_금신리`). `군`/`시` 접미사는 뗀다.

## 새 이름을 추가할 때

1. **경로 패턴에 글자로 박히는가?** 아니오 → 한글 그대로 쓰고 이 문서에 등재하지 않는다
2. 예 → 영문 `kebab-case` 로 정하고 **이 표에 추가**
3. rule을 만든다면 `paths:` 에 그 이름이 정확히 들어갔는지 확인
4. **세션을 재시작하고** 해당 폴더의 파일을 열어 rule이 실제로 주입되는지 확인
   - 검증 전에 그 rule 파일을 직접 열면 중복 제거 때문에 **테스트가 무효**가 된다
   - 절차: `repo_restructure_plan.md` §1
