# 환경영향평가 보고서 AI 자동화 PoC 결과 보고서

> 작성일: 2026-02-20
> 대상: 소규모 환경영향평가 — 소음·진동 파트 (태양광 발전시설)

---

## 1. PoC 개요

### 1.1 목적
소규모 환경영향평가 보고서의 특정 파트(소음·진동)에 대해, AI를 활용한 초안 자동 생성이 실무적으로 가능한지 검증합니다.

### 1.2 테스트 설계

| 항목 | 내용 |
|------|------|
| 테스트 대상 파트 | 소음·진동 (섹션 7.2.7) |
| 레퍼런스 보고서 | 4개 세트 (여주 광대리, 원주 무장리, 청양 매곡리, 천안 화덕리) |
| 테스트 방법 | 괴산 금신리 사업의 인풋(사업개요 + 측정성적서)만 제공하고, AI가 소음·진동 본문 초안을 생성 |
| 비교 대상 | 실무자가 실제로 작성한 괴산 금신리 소음·진동 본문 |
| 사용 AI 모델 | Claude Opus 4.6 (Anthropic) |

### 1.3 검증 방식
- 레퍼런스 4개 중 **괴산 금신리를 "정답지"로 분리**
- 나머지 4개 레퍼런스 + 괴산 인풋만 AI에게 제공
- AI 생성 초안을 정답지와 항목별 비교

### 2.1 수령 자료 현황

5개 태양광 사업 세트를 분석하였으며, 각 세트는 사업개요(HWP), 소음·진동 본문(HWP), 삽도(JPG), 측정성적서(PDF/HWPX)로 구성되어 있습니다.

|---|--------|---------|-------------|------|---------|
| 1 | 여주 광대리 | O | O | 44장 | — |
| 2 | 원주 무장리 | O | O | 15장 | O |

### 2.2 문서 구조 분석

5개 보고서의 소음·진동 파트를 비교 분석한 결과, **구조 일치도 90~95%**로 매우 정형적인 문서임을 확인하였습니다.

**공통 구조:**
```
가. 현황
   ├── 현황조사내용 표
   ├── 소음·진동 발생원 현황 (서술)
   ├── 측정지점 / 측정일시 / 측정결과 (표)
   └── 법령 기준표 3종 + 환경분쟁 기준
나. 영향예측
   ├── 영향예측내용 표
   ├── 영향예측지점 표
   ├── 예측방법 (공식 + 장비 표)
   └── 예측결과 (소음·진동 각각의 목표/합성/이격거리별/정온시설별 표)
다. 저감방안
   ├── 환경보전목표 표
   └── 공사시 저감방안 (일반 + 소음 + 진동)
```

### 2.3 고정 vs 가변 영역

| 영역 | 비율 | 설명 |
|------|------|------|
| **고정 영역** | ~45% | 법령 인용표, 예측 공식, 저감방안 문구 등 모든 보고서에서 동일한 내용 |
| **단순 치환 영역** | ~40% | 사업명, 위치, 측정값, 예측값 등 숫자·지명만 바뀌는 내용 |
| **생성 필요 영역** | ~15% | 발생원 현황 서술, 사업별 특이사항 등 |

**핵심 발견: 전체의 약 85%가 "복사 + 치환"으로 생성 가능한 구조입니다.**

## 3. AI 생성 테스트 결과

### 3.1 평가 항목별 결과

| 평가 항목 | 결과 | 상세 |
|----------|------|------|
| **문서 구조 일치도** | **100%** | 모든 섹션이 정답지와 동일한 순서·구조로 생성됨 |
| **고정 내용 재현율** | **100%** | 법령표 3종, 환경분쟁 기준, 건설기계류 표, 저감방안 문구 등 모두 정확히 재현 |
| **변수 치환 정확도** | **100%** | 사업명, 측정값(소음 49/44dB, 진동 15/10dB), 기준값("다"지역 65/55) 등 16개 변수 모두 정확 |
| **문체·서술 품질** | **95%** | 보고서 문체("~으로 조사되었다", "~할 계획이다") 완벽 재현 |
| **환각(Hallucination)** | **0건** | 인풋에 없는 수치를 지어내지 않음 |

### 3.2 정확히 생성된 항목 (인풋만으로 가능)

- 현황조사내용 표 (조사시기, 항목, 범위, 방법)
- 측정지점 정보 (주소, 지점명)
- 소음 측정결과 표 (4회차 주간 + 2회차 야간 + 평균 + 기준)
- 진동 측정결과 표 (2회차 주간 + 1회차 심야 + 평균 + 기준)
- 법령 기준표 3종 (소음환경기준, 생활소음규제기준, 생활진동규제기준)
- 환경분쟁 피해배상액 산정기준
- 건설기계류 소음도 표
- 합성소음도 (76.6 dB(A)) 및 합성진동레벨 (36.4 dB(V))
- 이격거리별 소음도·진동도 표
- 소음·진동 목표기준 설정
- 저감방안 전체 (일반 + 저소음장비 + 분산투입 + 방음판넬)
- 환경보전목표 표

### 3.3 누락된 항목 (현장조사 데이터 필요)

| 누락 항목 | 데이터 출처 | 보완 방법 |
|----------|-----------|---------|
| 영향예측지점 (지점명, 방향, 이격거리, 좌표) | 현장조사 | 실무자가 현장조사 후 입력 |
| 정온시설별 예측소음도·진동도 | 이격거리 기반 계산 | 예측지점 입력 시 자동 계산 가능 |
| 최종 저감대책 후 예측소음도 | 위 결과에 저감효과 적용 | 자동 계산 가능 |
| 투입장비 일 작업량·시간당 작업량 | 토공 설계자료 | 대기질편 토공량 데이터 연동 |

**이 항목들은 "AI의 한계"가 아니라 "인풋 데이터 부족"이 원인이며, 해당 데이터를 추가 제공하면 AI가 자동으로 채울 수 있습니다.**

## 4. PoC 결론

### 판단: GO (진행 가능)

소음·진동 파트에 대해 AI 자동화는 **실무적으로 충분히 가능**합니다.

| 판단 기준 | 목표 | 결과 |
|----------|------|------|
| 구조 일치도 80% 이상 | 80% | **100%** |
| 치명적 환각 없음 | 0건 | **0건** |
| 실무자가 디벨롭 가능한 수준 | — | **가능** (현장조사 데이터만 추가 입력) |

### 자동화 가능 범위

```
전체 소음·진동 파트
├── AI 자동 생성 가능: ~80%
│   ├── 법령 기준표 3종 + 환경분쟁 기준 (고정)
│   ├── 현황 조사내용·측정결과 (인풋에서 추출)
│   ├── 건설기계류 표·예측 공식 (고정)
│   ├── 합성소음도·진동레벨 계산 (자동)
│   ├── 이격거리별 감쇠 표 (자동)
│   └── 저감방안 전체 (고정)
│
└── 실무자 입력 필요: ~20%
    ├── 영향예측지점 (현장조사)
    ├── 정온시설별 예측값 (자동 계산 가능, 이격거리만 입력)
    └── 발생원 현황 특이사항 (사업별 서술)
```

## 5. 실무 적용 시 기대 효과

### 5.1 작업 시간 단축

| 단계 | 기존 방식 | AI 적용 후 |
|------|---------|-----------|
| 보고서 구조·법령표 작성 | 1~2일 | **자동 생성 (수 분)** |
| 측정 데이터 반영 | 0.5일 | **자동 치환 (수 분)** |
| 영향예측 계산·표 작성 | 1일 | **이격거리 입력 시 자동 계산** |
| 저감방안 작성 | 0.5일 | **자동 생성 (수 분)** |
| 검토·수정 | 1일 | 0.5~1일 |
| **합계** | **4~5일** | **1~1.5일** |

### 5.2 품질 향상

- 법령 인용 오류 제거 (최신 법령 기준표를 고정 탑재)
- 변수 치환 누락 방지 (동일 변수의 일관성 자동 보장)
- 계산 오류 제거 (합성소음도, 거리감쇠 자동 계산)

## 6. 향후 확장 로드맵

### Phase 1: 소음·진동 파트 자동화 (현재 PoC 완료)
- 소음·진동 본문의 80% 자동 생성
- 실무자는 현장조사 데이터만 입력

### Phase 2: 대기질 파트 확장
- 대기질 파트도 동일한 정형 구조로 예상
- 대기질 측정성적서(PM10, PM2.5, SO2, NO2, O3, CO) 데이터 자동 반영
- PoC와 동일한 방식으로 확장 가능

### Phase 3: 전체 보고서 통합
- 사업개요(제1장) + 각 환경 파트(대기질, 수질, 소음·진동 등) 통합 자동화
- 삽도(JPG) 자동 삽입
- HWP/HWPX 최종 출력물 자동 생성

### Phase 4: 운영 시스템 구축
- 웹 기반 입력 인터페이스 (사업개요 + 측정성적서 업로드)
- 보고서 자동 생성 + 실무자 검토 워크플로우
- 레퍼런스 DB 축적을 통한 품질 지속 개선

## 7. 기술적 세부사항

### 7.1 HWP 파일 처리
- HWP(바이너리): `olefile` 라이브러리로 텍스트 추출 성공 (10개 파일 100% 추출)
- HWPX(XML 기반): ZIP 해제 후 XML 파싱으로 텍스트 추출 성공
- PDF/JPG 측정기록부: 직접 읽기 가능

### 7.2 AI 모델 컨텍스트
- 레퍼런스 5세트 + 인풋 1세트 전체를 단일 컨텍스트에 투입 가능
- 총 토큰 수: 약 200,000~300,000 토큰 (Claude Opus 4.6 컨텍스트 한도 내)
- 일괄 생성(전략 B) 적용 가능

### 7.3 테스트 환경
- AI 모델: Claude Opus 4.6 / Claude Sonnet 4.6
- 텍스트 추출: Python (olefile, xml.etree, zipfile)
- 비교 분석: 수동 대조 + 자동 구조 비교
