## 4. 생성 전에 이미 아는 문제 3가지 ⚠️

**검증에서 이 세 가지가 오류로 잡히더라도 놀랄 일이 아니다.** 미리 특정해 둔다.

### 4-1. 표 29 가설방음판넬 열이 **미구현**

`generate.py tables_noise_vib()` 의 표 29 는 9칸 고정이다:

```python
fill_row(hwp, [구분, 지점명, 이격거리, 예측치, 저소음후, 분산후, 최종예측치, 목표, 비고])
```

rule §3-3 은 **청양만 방음판넬 열이 추가된 10칸**이라고 적고 있다. 지금 코드로는:

- 방음판넬 열이 나오지 않는다
- **최종예측치 = 분산후(72.7)** 가 되어 P-1 이 `상회` 로 남는다 (정답은 방음판넬 적용 후 `만족`)

→ **다음 개선 항목.** 열 추가는 한글 API 표 구조 조작이라 Windows 없이 검증할 수 없어 이번엔 손대지 않았다.

### 4-2. 저감 계산의 **0.1 반올림 경로** — 원인을 특정했다 ★

rule §3-3-③ 은 청양 P-1 을 `72.6 − 12.64 = 59.96` 으로 적는데, 우리 계산은 **72.7 / 12.66** 이다.

역산해 보면 정답은 이 경로다:

```
저소음 후 합성 75.6  →  분산 후 합성 70.7 (= 75.6 − 4.9)   ← 여기서 반올림
   →  P-1: 70.7 − 20·log10(12/15) = 72.638  →  72.6
   →  방음판넬 = 72.638 − 60 = 12.638  →  12.64      ✅ rule 과 일치
```

우리 `mitigation_series()` 는 **거리 감쇠를 먼저** 하고 저감을 적용한다(중간 반올림 없음):

```
P-1: attenuate(76.5986, 12) = 78.537 → 저소음 77.564 → 분산 72.664 → 72.7
```

> ⚠️ **그런데 rule §3-3 은 "중간값을 반올림하지 말라"고 명시**하고 있다 — 괴산 P-1 이 `56.04 → 55.07 → 51.77` 로 가야 정답(55.1/51.8)이 나온다는 근거로. **두 사업이 서로 다른 경로를 요구한다.**
>
> 이것이 rule §6-2-1 의 미해결 항목(*"표 29 저소음후 3행이 0.1 어긋남 — 반올림 경로"*)과 같은 뿌리다.
> **청양은 10개 지점이라 패턴을 판별할 표본이 가장 크다.** 검증 시 어느 행이 0.1 어긋나는지 전수 기록할 것.

### 4-3. 일작업량이 `[확인 필요]`

표 19 의 작업량·시간당작업량 두 칸이 비워진다. 설계도서/대기질편(7.2.2) 자료가 없어 **원칙대로 채우지 않았다**(환각 금지). 정답에는 값이 있을 것이므로 2칸 오류로 잡힌다 — 지식·코드 문제가 아니다.
