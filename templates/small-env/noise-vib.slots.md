# 베이스 문서 빈칸 명세 — small-env / noise-vib

> **용도**: 6단계(Windows) 작업 지시서. 원주 무장리 골든셋 `원본.hwpx` 를 열어 **아래 문자열을 빈칸 토큰으로 바꾸면** 베이스 문서 `templates/small-env/noise-vib.hwpx` 가 된다.
> **작성**: 2026-07-29 · 근거는 `golden/small-env/원주_무장리/noise-vib.txt` 실측 (줄 번호 표기)
> **짝**: 토큰 이름은 `engine/generate.py` 의 `slots_noise_vib()` 반환 키와 **정확히 일치해야 한다.** 어긋나면 치환이 조용히 안 된다 — 엔진이 마지막에 잔여 토큰을 검사한다.

---

## 왜 원본을 그대로 쓰지 않고 빈칸을 뚫나

PoC는 원주 원본을 템플릿으로 쓰고 값을 덮어썼다. 그래서 **덮어쓰기를 놓치면 원주 값이 그대로 남았다** — 2차 PoC의 `MISSING` 7건이 전부 이것이고, 틀린 값이 그럴듯해 보여 발견이 늦다.

빈칸이면 누락이 **`{{...}}` 로 눈에 보인다.** 엔진도 저장 후 잔여 토큰을 검사해 경고한다.

---

## 작업 방법

1. `golden/small-env/원주_무장리/원본.hwpx` 를 **복사**해서 연다 (원본을 직접 편집하지 말 것)
2. 아래 표의 `찾을 문자열` → `토큰` 으로 바꾼다 (한글 찾기/바꾸기)
3. `templates/small-env/noise-vib.hwpx` 로 저장
4. 검증: `python engine/generate.py small-env noise-vib 괴산_금신리 --raw-dir ...`

> ⚠️ **가운뎃점 주의.** `·`(U+00B7) / `ㆍ`(U+318D) / `․`(U+2024) 가 자리마다 다르다. **골든셋에서 복사해 붙여넣을 것** — 손으로 치면 매칭에 실패한다. 아래 표의 문자열도 복사해서 쓴다.

### ⚠️ 14·16번 — 문장 구조가 다르다

원주는 소음 `있을`, 진동 `없을` 이다. 괴산 정답은 둘 다 `미미할` 이다. 2차 PoC에서 진동 문구가 `없을 것` 으로 남아 Minor 오류가 났다. **두 자리 모두 반드시 토큰으로 만들 것.**

### ⚠️ 6~9번 — 숫자만 바꾼다

`45.0dB(A)` 에서 **`45.0` 만** 토큰으로 만들고 `dB(A)` 는 남긴다. 단위까지 토큰에 넣으면 엔진 출력(`49`)에 단위가 빠진다.

## B. 표 — 빈칸을 뚫지 않는다 (엔진이 셀 단위로 편집)

아래 표는 `tables_noise_vib()` 가 **셀을 찾아 덮어쓴다.** 빈칸을 뚫으면 오히려 검색 앵커가 사라져 실패한다. **원주 값 그대로 둘 것.**

| 표 | 앵커 문자열 | 엔진 동작 |
|:--:|---|---|
| 6 소음측정결과 | `N - 1` | 측정값 8칸 덮어쓰기 |
| 7 진동측정결과 | `V - 1` (skip=1) | 측정값 5칸 |
| 14 영향예측지점 | `XTM` | 행 수 조절 + PP 데이터 |
| 21 이격거리별 소음도 | `구분(m)` | 거리 + 소음도 계산값 |
| 22 예측소음도 | `예측소음도` | 행 수 조절 + PP별 계산 |
| 24 이격거리별 진동도 | `구분(m)` (skip=1) | 진동도 계산값 |
| 25 예측진동도 | `예측진동도` | 행 수 조절 + PP별 계산 |
| 29 최종 저감대책 | `최종예측치` | 행 수 조절 + 저감 3단계 계산 |

**앵커 문자열은 절대 건드리지 말 것.** 특히 `구분(m)` 은 표 21·24에 모두 있어 순서에 의존한다 (`skip=1`).

### 표 5·9~12는 예외

| 표 | 처리 |
|:--:|---|
| 5 측정지점 | 주소·이격거리·비고는 A의 3번 토큰 + 셀 편집. **앵커 `N·V - 1` 유지** |
| 9~12 법령표 | **전부 그대로.** 볼드/음영만 수동 보정 (`/validate-report` 6단계) |

## A-2. 6단계 실행에서 추가한 자리 (2026-07-31) ★

§D 지시("실제 문서를 보고 본문에 노출된 자리가 있으면 토큰을 추가")대로 실측해 **7개를 더 뚫었다.**
전부 **원주 값이 그대로 남으면 틀리는 자리** — 2차 PoC `MISSING 7건`의 정체다.

| 토큰 | 찾을 문자열 (원주) | 왜 필요한가 |
|---|---|---|
| `{{측정지점_이격거리}}` | `250` (표 5) | 엔진이 표 5를 셀 편집하지 않는다. 괴산 `25m` |
| `{{측정지점_비고}}` | `축사 인근` (표 5) | 〃 |
| `{{소음환경기준_지역}}` | `소음환경기준(일반지역 “나” 지역)` (표 6) | 괴산은 `“다”` |
| `{{소음환경기준_주간}}` · `{{소음환경기준_야간}}` | `55` · `45` (표 6) | 괴산은 `65` · `55` |
| `{{일작업량}}` | `201.22` (표 19) | 괴산 `190` |
| `{{목표소음_축사}}` · `{{목표진동_축사}}` | `가축피해 강화기준 60dB(A)` · `57dB(V)` | 괴산과 같지만 사업마다 갈릴 수 있다 |

**숫자 셀은 찾기/바꾸기로 못 잡는다** (`55`·`45`는 문서 전체에서 유일하지 않다).
앵커 셀(`소음환경기준(일반지역`)을 찾아 **오른쪽으로 이동해** 넣는다 — `build_template.py` 의 `cells` 명세.

### 아직 안 뚫린 자리 — 다음에 할 것

| 찾을 문자열 (원주) | 정답(괴산) | 판정 |
|---|---|:--:|
| `P-1 지점을 제외한 전 지점에서 기준치를 만족` | `전 지점에서 기준치를 만족` | **MISSING** |

rule §5 조건부 문구인데 빠뜨렸다. `slots_noise_vib()` 에 키를 추가하고 여기 A절에도 넣어야 한다.

### 만드는 방법 — 수작업 대신 스크립트

```powershell
python engine\build_template.py small-env noise-vib --dry-run   # 매칭 검사만 (한글 불필요)
python engine\build_template.py small-env noise-vib             # 실제 생성 + 토큰 대조
```

손으로 치면 가운뎃점 3종과 스마트따옴표에서 매칭이 깨진다. 문자열을 `build_template.py` 에 박아 뒀다.

> ⚠️ **토큰이 XML 런 경계로 쪼개지는 일이 있다.** 원본에 글자 서식 경계나 형광펜(`hp:markpen`)이 걸쳐 있으면
> `{{진동</hp:t>…<hp:t>_주간평균}}` 처럼 나뉜다. 한글 찾기/바꾸기는 이래도 되지만 `generate.py` 의
> **잔여 토큰 검사가 무력해진다.** `build_template.py` 의 `normalize()` 가 다시 넣어 병합한다.

## D. 작업 후 확인

```bash
# 1. 빈칸이 제대로 뚫렸는지 (Mac 에서도 가능)
python engine/extract.py templates/small-env/noise-vib.hwpx | grep -o '{{[^}]*}}' | sort -u

# 2. 명세와 대조 — 아래와 일치해야 한다 (14종)
#    사업명 조사시기 측정지점_주소 측정일시 측정결과_도입
#    소음_주간평균 소음_야간평균 진동_주간평균 진동_심야평균
#    측정지점도_캡션 예측지점_수 최인접_이격거리 소음영향_서술
#    진동영향_서술 목표기준_지역문자

# 3. 생성 (Windows)
python engine/generate.py small-env noise-vib 괴산_금신리 --raw-dir "<삽도 경로>"
```

엔진이 저장 후 **잔여 토큰과 `[확인 필요]` 를 자동 검사**한다.

> `slots_noise_vib()` 는 위 15종 외에 `측정지점_이격거리`·`측정지점_비고`·`공종`·`일작업량`·`소음환경기준_*`·`생활진동규제_*`·`목표소음_*`·`목표진동_*` 도 반환한다. 이들은 **표 안에 있어 셀 편집으로 처리**되거나, 원주 값이 그대로 맞아 빈칸이 불필요한 것들이다. 6단계에서 실제 문서를 보고 **본문에 노출된 자리가 있으면 토큰을 추가**하고 이 명세를 갱신한다.
